# 01. 數字系統與資料表示

> **一句話**：韌體世界裡所有東西最後都是 0 與 1。看懂**進位轉換、二補數、端序、浮點數**，才能讀懂暫存器、通訊封包與記憶體傾印（memory dump）。

---

## 1. 為什麼韌體特別在意數字表示 🟢

| 情境 | 需要的知識 |
|---|---|
| Datasheet 寫「寫入 `0x40` 到 CTRL 暫存器」 | 十六進位 ↔ 二進位 |
| 感測器回傳 `0xFF9C` 代表溫度 | 二補數（有號數） |
| 透過 UART 收到 4 個 byte 組成一個整數 | 端序（Endianness） |
| ADC 回傳 12-bit 值要轉成電壓 | 定點數 / 比例換算 |
| 除錯器看到記憶體 `00 00 80 3F` | IEEE 754 浮點（= 1.0f，小端序） |

## 2. 進位制轉換 🟢

### 2.1 基本單位

| 名稱 | 位元數 | 範圍（無號） |
|---|---|---|
| bit | 1 | 0～1 |
| nibble | 4 | 0～15（剛好一個十六進位數字） |
| byte | 8 | 0～255 |
| half-word（ARM） | 16 | 0～65535 |
| word（ARM 32-bit） | 32 | 0～4,294,967,295 |

> 注意：「word」的長度依架構而定。ARM 的 word 是 32-bit，x86 的 WORD 是 16-bit（歷史因素）。

### 2.2 轉換方法

**十進位 → 二進位**：連續除以 2，取餘數由下往上讀。

```
13 ÷ 2 = 6 餘 1
 6 ÷ 2 = 3 餘 0
 3 ÷ 2 = 1 餘 1
 1 ÷ 2 = 0 餘 1    → 13 = 0b1101
```

**二進位 → 十進位**：每一位乘上 2 的冪次。

```
0b1101 = 1×8 + 1×4 + 0×2 + 1×1 = 13
```

**二進位 ↔ 十六進位（最常用）**：每 4 bit 一組直接對照。

```
0b 1010 1111 0011 = 0xAF3
     A    F    3
```

**八進位**：每 3 bit 一組。韌體少用，但 C 語言 `0` 開頭的常數是八進位（`010` = 8，常見陷阱）。

### 2.3 必背對照表

| 十進位 | 二進位 | 十六進位 |
|---|---|---|
| 0 | 0000 | 0 |
| 5 | 0101 | 5 |
| 10 | 1010 | A |
| 12 | 1100 | C |
| 15 | 1111 | F |

必背的 2 的冪次：2⁸=256、2¹⁰=1024（1 KiB）、2¹⁶=65536、2²⁰≈1M、2³²≈4.29G。

> **KB vs KiB**：韌體與 Flash 容量通常用 1024 為單位（KiB），但規格書有時混用。看到「64 KB Flash」通常是 65536 bytes。

## 3. 有號數：二補數（Two's Complement）🟢

### 3.1 為什麼用二補數

現代 CPU 幾乎都用二補數表示負數，因為**加法與減法可以用同一個硬體電路**，且 0 只有一種表示法。

### 3.2 計算方式

**求負數**：**反轉所有位元，再加 1**。

```
 5 = 0000 0101
反轉 = 1111 1010
 +1  = 1111 1011  → -5（8-bit）
```

**判讀**：最高位元（MSB）為 1 即為負數。快速判讀法：最高位代表 -2⁽ⁿ⁻¹⁾。

```
1111 1011 = -128 + 64 + 32 + 16 + 8 + 0 + 2 + 1 = -5
```

### 3.3 範圍

| 型別 | 範圍 |
|---|---|
| `int8_t` | -128 ～ 127 |
| `uint8_t` | 0 ～ 255 |
| `int16_t` | -32768 ～ 32767 |
| `int32_t` | -2,147,483,648 ～ 2,147,483,647 |

> 負數比正數多一個，所以 `-(-128)` 在 8-bit 會溢位，仍是 -128。

### 3.4 符號擴展（Sign Extension）

把小型別的有號數放進大型別時，要**複製最高位元**補滿。

```
int8_t  -5 = 1111 1011
int16_t -5 = 1111 1111 1111 1011
```

實務陷阱：感測器回傳 12-bit 有號值，必須自己做符號擴展：

```c
int16_t raw = read_12bit();            // 例：0x0FFF
if (raw & 0x0800) raw |= 0xF000;       // 第 11 位是符號位 → 補 1
// 或：int16_t v = (int16_t)(raw << 4) >> 4;  （依賴算術右移，見第 04 章）
```

## 4. 溢位（Overflow）與環繞（Wrap-around）🟡

| 型別 | 溢位行為（C 語言） |
|---|---|
| 無號整數 | **定義良好**：模 2ⁿ 環繞，`255 + 1 = 0`（uint8_t） |
| 有號整數 | **未定義行為（UB）**：編譯器可假設不會發生並做出意外最佳化 |

**實務應用：計時器環繞**。`uint32_t` 的毫秒計數約 49.7 天會環繞，正確寫法：

```c
// 正確：利用無號減法的環繞特性，即使 tick 溢位也正確
if ((uint32_t)(now - start) >= timeout_ms) { /* 逾時 */ }

// 錯誤：tick 環繞時會判斷錯誤
if (now >= start + timeout_ms) { ... }
```

## 5. 端序（Endianness）🟡

多 byte 資料在記憶體中的排列順序。

以 `0x12345678` 存在位址 `0x1000` 為例：

| 位址 | 0x1000 | 0x1001 | 0x1002 | 0x1003 |
|---|---|---|---|---|
| **小端序（Little Endian）** | 78 | 56 | 34 | 12 |
| **大端序（Big Endian）** | 12 | 34 | 56 | 78 |

- **小端序**：低位 byte 放低位址。ARM Cortex-M（預設）、x86、RISC-V、ESP32
- **大端序**：高位 byte 放低位址。**網路位元組順序（Network Byte Order）**、部分舊式處理器、Modbus 暫存器內容、許多感測器的暫存器排列

判斷本機端序：

```c
uint32_t x = 1;
int is_little = (*(uint8_t *)&x == 1);
```

可攜的封包解析（**不依賴本機端序**，面試推薦寫法）：

```c
uint32_t read_be32(const uint8_t *p) {
    return ((uint32_t)p[0] << 24) | ((uint32_t)p[1] << 16) |
           ((uint32_t)p[2] << 8)  |  (uint32_t)p[3];
}
```

> 不要用 `*(uint32_t *)buf` 直接轉型讀取：同時有**端序問題、未對齊存取（可能觸發 HardFault）、違反 strict aliasing** 三個風險。

## 6. 浮點數（IEEE 754）🟡

### 6.1 單精度（float，32-bit）

```
| S (1) | Exponent (8) | Mantissa (23) |
值 = (-1)^S × 1.Mantissa × 2^(Exponent − 127)
```

例：`1.0f` = `0x3F800000`；`-2.0f` = `0xC0000000`。

### 6.2 韌體需要知道的事

| 重點 | 說明 |
|---|---|
| 精度有限 | `0.1f + 0.2f != 0.3f`，比較浮點數要用誤差範圍 |
| 硬體 FPU | Cortex-M4F/M7/M33 有單精度 FPU；M0/M0+/M3 沒有，浮點運算用軟體模擬，**慢數十倍** |
| `double` 陷阱 | 多數 MCU 的 FPU 只支援單精度，`3.14`（double 常數）會觸發軟體運算，應寫 `3.14f` |
| ISR 中用浮點 | 會增加 context 儲存成本（Cortex-M 有 lazy stacking 機制緩解） |
| 特殊值 | NaN、±Inf、非正規數（denormal） |

## 7. 定點數（Fixed-Point）🟡

沒有 FPU 的 MCU 常用整數模擬小數。**Q 格式**：Qm.n 表示 m 位整數、n 位小數。

```
Q15（16-bit）：值 = raw / 32768，範圍 -1 ～ 0.99997
Q16.16（32-bit）：值 = raw / 65536
```

實務技巧：**放大整數運算**。溫度 25.37°C 存成 `2537`（單位 0.01°C），避免浮點。

ADC 換算範例（12-bit、參考電壓 3.3V）：

```c
// 電壓(mV) = raw × 3300 / 4095，先乘後除避免精度遺失，注意中間值不可溢位
uint32_t mv = (uint32_t)raw * 3300u / 4095u;
```

## 8. 其他編碼 🟢

| 編碼 | 用途 |
|---|---|
| **BCD**（二進位編碼十進位） | 每 4 bit 表示一個十進位數字。RTC 晶片（如 DS3231）的時間暫存器常用：`0x59` 代表 59 秒 |
| **ASCII** | `'0'` = 0x30、`'A'` = 0x41、`'a'` = 0x61；數字字元轉數值：`c - '0'` |
| **格雷碼（Gray Code）** | 相鄰數值只差 1 bit，用於旋轉編碼器、跨時脈域計數器，避免讀取中間錯誤值 |
| **CRC / Checksum** | 資料完整性檢查（見第 11 章） |

BCD 轉換：

```c
uint8_t bcd_to_bin(uint8_t b) { return (b >> 4) * 10 + (b & 0x0F); }
uint8_t bin_to_bcd(uint8_t v) { return (uint8_t)(((v / 10) << 4) | (v % 10)); }
```

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. 把 0xA5 轉成二進位與十進位。

`0xA5` = `1010 0101` = 128 + 32 + 4 + 1 = **165**。若視為 `int8_t`，MSB 為 1 → 165 − 256 = **-91**。

### Q2. 8-bit 的 -1 是多少？`(uint8_t)-1` 呢？

-1 的二補數為 `1111 1111` = `0xFF`。轉成 `uint8_t` 即為 **255**。這也是為什麼 `uint32_t x = -1;` 會得到 `0xFFFFFFFF`，常用來表示「全部位元為 1」。

### Q3. 什麼是大端序與小端序？如何判斷？網路傳輸用哪一種？

見第 5 節。判斷：將 `uint32_t x = 1` 的第一個 byte 讀出，為 1 是小端序。網路傳輸用**大端序**，C 中以 `htonl()` / `ntohl()` 轉換。韌體實務上最好用**移位組合**的方式解析，與本機端序無關。

### Q4. 寫一個函式交換 32-bit 整數的端序。

```c
uint32_t swap32(uint32_t x) {
    return ((x & 0x000000FFu) << 24) |
           ((x & 0x0000FF00u) << 8)  |
           ((x & 0x00FF0000u) >> 8)  |
           ((x & 0xFF000000u) >> 24);
}
```

補充：GCC 提供 `__builtin_bswap32()`，ARM 有單一指令 `REV`，編譯器通常會把上面寫法最佳化成 `REV`。

### Q5. 有號整數溢位與無號整數溢位有何不同？

無號整數溢位是**定義良好的模運算**；有號整數溢位是**未定義行為**，編譯器可能做出「假設不會溢位」的最佳化，例如把 `if (x + 1 > x)` 直接當成永遠成立。需要環繞語意時請使用無號型別。

### Q6. 為什麼 `0.1 + 0.2 != 0.3`？韌體中如何處理小數？

0.1 無法以二進位精確表示（像 1/3 在十進位是無限小數），會有捨入誤差。比較時用 `fabsf(a - b) < EPS`。韌體中常用**定點數**或**放大整數**（以 0.01 為單位）處理，避免在無 FPU 的 MCU 上做慢速浮點運算。

### Q7. 感測器回傳 16-bit 大端序的有號溫度值，`buf[0]=0xFF, buf[1]=0x9C`，解析度 0.1°C，溫度是多少？

組合：`(int16_t)((buf[0] << 8) | buf[1])` = `0xFF9C` = -100 → **-10.0°C**。

關鍵點：一定要**先轉成 `int16_t`** 才能得到負數；若直接存進 `int32_t` 會得到 65436。

### Q8. 計時器 tick 用 `uint32_t` 毫秒計數，多久會溢位？如何寫逾時判斷才正確？

2³² ms ≈ **49.7 天**。正確寫法 `(uint32_t)(now - start) >= timeout`，利用無號減法環繞特性，即使跨越溢位點也正確。

## 過時技術（知道就好）

- **一補數（One's Complement）、符號-大小表示法**：早期電腦使用，有 +0 與 -0 兩種零。C23 標準已規定有號整數**必須**為二補數。
- **大端序 CPU（Motorola 68k、早期 PowerPC）**：新設計少見，但大端序仍廣泛存在於網路協定與感測器資料格式。

## 本章回顧

- 十六進位 ↔ 二進位：每 4 bit 一組，要能心算
- 負數 = 反轉 + 1；MSB 為符號位；小轉大要做符號擴展
- 無號溢位安全環繞，有號溢位是 UB
- ARM 是小端序、網路是大端序；解析封包用移位組合
- 沒有 FPU 時用定點數；浮點常數記得加 `f`
