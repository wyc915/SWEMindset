# 11. 有線通訊介面與協定設計

> **一句話**：韌體每天都在跟其他晶片「講話」。**UART、I²C、SPI、CAN** 是面試必考四大天王；能說出**時序、優缺點、除錯方法**就贏一半。

---

## 1. 基本名詞 🟢

| 名詞 | 說明 |
|---|---|
| **同步 / 非同步** | 同步有共用時脈線；非同步靠雙方約定速率 |
| **全雙工 / 半雙工 / 單工** | 同時雙向 / 輪流雙向 / 單向 |
| **串列 / 並列** | 一條線逐 bit 傳 / 多條線同時傳（現代以串列為主） |
| **單端 / 差動** | 對地量測 / 兩條線的電壓差（抗雜訊、可長距離：RS-485、CAN、USB、乙太網路） |
| **Master / Slave** | 新規範多改稱 **Controller / Target**（I²C、I3C）、**Main / Subnode**（SPI 的 MOSI→**SDO/PICO**） |

## 2. UART 🟢

### 2.1 訊框格式

```
閒置(高) ─┐ Start ┌─D0─D1─D2─D3─D4─D5─D6─D7─[Parity]─┌ Stop ─ 閒置
          └───────┘                                   (高)
```

- 常見設定 **8N1**：8 資料位元、無同位、1 停止位元 → 每個 byte 傳 10 bit
- **鮑率（Baud Rate）**：9600、115200、921600…
- **LSB 先傳**
- 實際吞吐量：115200 bps / 10 ≈ **11.5 KB/s**

### 2.2 重點

| 項目 | 說明 |
|---|---|
| 接線 | TX ↔ RX **交叉連接**，**必須共地** |
| 鮑率誤差 | 雙方誤差總和需 < 約 3～5%，內部 RC 時脈可能不夠準 |
| 流量控制 | 硬體 RTS/CTS、軟體 XON/XOFF |
| 錯誤 | Framing Error（停止位錯誤 → 鮑率不對）、Overrun（來不及讀）、Parity Error、Noise |
| 電氣標準 | TTL（3.3V）、**RS-232**（±12V，反相）、**RS-485**（差動、多點、1200m） |
| USART | 支援同步模式的 UART |
| LIN | 基於 UART 的低成本車用匯流排（車窗、座椅） |

**亂碼排查**：鮑率 → 時脈設定 → 共地 → TX/RX 接反 → 電位（RS-232 vs TTL）→ 示波器量 bit 寬度（1/115200 ≈ 8.68µs）。

## 3. I²C 🟡

### 3.1 基本特性

- **兩條線**：SDA（資料）、SCL（時脈），**開汲極 + 上拉電阻**
- 多 Controller、多 Target，用 **7-bit 位址**（少數 10-bit）區分
- 速度：Standard 100kHz、Fast 400kHz、Fast-mode Plus 1MHz、High-speed 3.4MHz
- 半雙工，適合板上短距離

### 3.2 傳輸時序

```
START：SCL 高時，SDA 由高變低
STOP ：SCL 高時，SDA 由低變高
資料：SCL 低時改變 SDA、SCL 高時 SDA 必須穩定

[S][7-bit 位址][R/W][ACK][資料 8-bit][ACK]...[P]
```

典型「讀取感測器暫存器」流程（**Repeated Start**）：

```
S | Addr+W | ACK | 暫存器位址 | ACK | Sr | Addr+R | ACK | Data | NACK | P
```

- **ACK**：接收方在第 9 個時脈拉低 SDA
- **NACK**：沒拉低 → 位址錯誤、裝置忙碌、或讀取最後一個 byte 時 Controller 主動 NACK 表示結束

### 3.3 進階機制

| 機制 | 說明 |
|---|---|
| **Clock Stretching** | Target 拉低 SCL 讓 Controller 等待（部分 Controller 實作不支援，如舊款樹莓派） |
| **仲裁（Arbitration）** | 多個 Controller 同時傳輸時，送出 1 卻讀到 0 的一方退出 |
| **匯流排卡死（Bus Hang）** | Target 在傳輸中被重置，持續拉低 SDA → **Controller 送出 9 個 SCL 時脈**讓 Target 完成傳輸，再送 STOP |
| 位址衝突 | 同型號感測器接在同一匯流排 → 用位址腳位選擇或 I²C 多工器（TCA9548A） |

### 3.4 I3C（新一代）🔴

MIPI I3C：與 I²C 相容、速度可達 12.5MHz（SDR）、支援**帶內中斷（IBI，不需額外中斷線）**、動態位址分配。手機與新感測器逐漸採用，**DDR5 記憶體模組的 SPD 匯流排也改用 I3C**。

## 4. SPI 🟡

### 4.1 基本特性

- **四條線**：SCK（時脈）、MOSI/SDO（主出）、MISO/SDI（主入）、CS/SS（片選，低電位有效）
- 全雙工：每送出一個 bit 同時收回一個 bit（**移位暫存器交換**）
- 無位址、無 ACK，每個 Target 需要**一條獨立 CS**（或菊鍊）
- 速度：數 MHz ～ 100MHz 以上

### 4.2 四種模式（必考）

| 模式 | CPOL | CPHA | 閒置時脈 | 取樣邊沿 |
|---|---|---|---|---|
| **0** | 0 | 0 | 低 | 第一個邊沿（上升沿） |
| 1 | 0 | 1 | 低 | 第二個邊沿（下降沿） |
| 2 | 1 | 0 | 高 | 第一個邊沿（下降沿） |
| **3** | 1 | 1 | 高 | 第二個邊沿（上升沿） |

- **CPOL**：閒置時 SCK 的電位
- **CPHA**：在第幾個邊沿取樣
- **雙方模式必須一致**，查 Target 的 Datasheet 時序圖。Mode 0 與 Mode 3 最常見

### 4.3 延伸

| 名稱 | 說明 |
|---|---|
| **Dual / Quad / Octal SPI（QSPI/OSPI）** | 多條資料線並行，用於外部 Flash / PSRAM，可記憶體映射執行（XIP） |
| 3-wire SPI | MOSI/MISO 共用一條線（半雙工） |
| 讀取時要送 dummy byte | 因為 SPI 是交換：要收資料就必須送出時脈 |

## 5. I²C vs SPI vs UART（面試總整理）🟡

| | UART | I²C | SPI |
|---|---|---|---|
| 線數 | 2 + GND | 2 + GND | 3 + N 條 CS + GND |
| 時脈 | 非同步 | 同步 | 同步 |
| 雙工 | 全 | 半 | 全 |
| 拓撲 | 點對點 | 匯流排（位址） | 匯流排（CS） |
| 速度 | 低～中 | 低～中 | **高** |
| 確認機制 | 無（可加同位） | **ACK/NACK** | 無 |
| 距離 | TTL 短；RS-485 長 | 板上短距離 | 板上短距離 |
| 優點 | 簡單、通用 | 線少、裝置多 | 快、簡單、全雙工 |
| 缺點 | 需準確時脈 | 慢、上拉影響速度、易卡死 | 線多、無確認 |

## 6. CAN / CAN FD（車用、工業）🔴

### 6.1 特性

- **差動雙線**：CAN_H、CAN_L，兩端各一個 **120Ω 終端電阻**
- 多主架構（Multi-master），**無位址，以訊息 ID 識別內容**
- ID 同時也是**優先權**：數值越小越優先
- **非破壞性位元仲裁**：顯性位（0）勝過隱性位（1），輸掉的節點自動轉為接收，**最高優先權訊息不受延遲**
- 內建 CRC、ACK、錯誤計數與 **Bus-Off** 機制（故障節點自動脫離匯流排）

### 6.2 版本比較

| | Classical CAN | CAN FD | **CAN XL** |
|---|---|---|---|
| 資料長度 | 0～8 bytes | 0～**64** bytes | 最多 2048 bytes |
| 速度 | ≤ 1 Mbps | 仲裁 1Mbps、資料段 2～8 Mbps | 資料段 10～20 Mbps |
| 狀態 | 舊車、工業 | **現代車用主流** | 新興，用於區域架構（Zonal） |

- ID：標準 11-bit、擴展 29-bit
- 上層協定：**CANopen**（工業）、**J1939**（商用車）、**UDS（ISO 14229）診斷**、ISO-TP（ISO 15765-2，分段傳輸長訊息）
- 硬體**過濾器（Filter）**：只接收感興趣的 ID，降低 CPU 負擔

| 介面 | 特性 | 用途 |
|---|---|---|

## 8. 資料完整性：Checksum 與 CRC 🟡

| 方法 | 偵錯能力 | 成本 |
|---|---|---|
| 同位元 | 只能偵測奇數個 bit 錯誤 | 最低 |
| Checksum（加總） | 弱，無法偵測位置交換 | 低 |
| **CRC** | 強，可偵測所有單一 / 雙 bit 錯誤、所有奇數錯誤、長度 ≤ n 的突發錯誤 | 中（可查表或硬體） |
| 雜湊（SHA-256） | 完整性 | 高 |
| **MAC / 數位簽章** | 完整性 + **真實性（防竄改）** | 高 |

**CRC 原理**：把資料視為多項式，除以生成多項式（GF(2) 上的除法 = XOR），餘數即 CRC。

常見：CRC-8（感測器，如 SHT3x）、**CRC-16/MODBUS**、CRC-16/CCITT、**CRC-32**（乙太網路、ZIP、韌體驗證）。

```c
// CRC-16/MODBUS（多項式 0xA001 為 0x8005 的位元反轉，初值 0xFFFF）
uint16_t crc16_modbus(const uint8_t *d, size_t n) {
    uint16_t crc = 0xFFFF;
    while (n--) {
        crc ^= *d++;
        for (int i = 0; i < 8; i++)
            crc = (crc & 1u) ? (uint16_t)((crc >> 1) ^ 0xA001u) : (uint16_t)(crc >> 1);
    }
    return crc;
}
```

## 9. 自訂通訊協定設計 🔴

常見的封包格式：

```
| SOF(0xAA) | LEN | CMD | SEQ | PAYLOAD (LEN bytes) | CRC16 |
```

| 設計問題 | 解法 |
|---|---|
| **訊框同步**（如何找到封包開頭） | 起始碼 + 長度 + CRC 驗證；或 **SLIP / COBS** 編碼（保證資料中不出現分隔符號） |
| 資料遺失 | 序號（SEQ）+ ACK + 逾時重傳 |
| 重複封包 | 依序號去重 |
| 版本相容 | 版本欄位、TLV（Type-Length-Value）格式 |
| 端序 | 協定明確規定（通常小端或網路大端），用移位序列化 |
| 解析 | **狀態機逐 byte 解析**（面試手寫題，見第 22 章） |
| 結構化資料 | **Protocol Buffers（nanopb）**、CBOR、MessagePack |

## 面試常問

### Q1. UART、I²C、SPI 比較？

見第 5 節表格。選擇原則：裝置多、腳位少、速度不高 → I²C；高速大量資料（Flash、顯示器）→ SPI；點對點、除錯、模組（GPS、BLE 模組）→ UART。

### Q2. I²C 為什麼需要上拉電阻？阻值怎麼選？

I²C 是開汲極輸出，裝置只能拉低，高電位靠上拉電阻。阻值取決於速度與匯流排電容：上升時間 ≈ 0.8473 × R × C 必須符合規格（100kHz ≤ 1000ns、400kHz ≤ 300ns）。常用 4.7kΩ（100k）、2.2kΩ（400k）。太大上升慢，太小電流超過規格（3mA）。

### Q3. I²C 讀取不到裝置（NACK）怎麼排查？

1. 位址是否正確（**7-bit 還是含 R/W 的 8-bit 寫法**——Datasheet 常混用，`0x68` vs `0xD0`）
2. 上拉電阻是否存在、電壓是否正確
3. 裝置是否供電、是否在重置狀態
4. 用 I²C 掃描程式掃描 0x08～0x77
5. 邏輯分析儀看 START、位址、ACK 位元
6. 是否有位址衝突、匯流排卡死

### Q4. SPI 的 CPOL 與 CPHA 是什麼？

見 4.2 節。

### Q5. SPI 如何連接多個裝置？

1. **每個裝置獨立 CS**（最常見），同一時間只拉低一個
2. **菊鍊（Daisy Chain）**：前一個的 MISO 接下一個的 MOSI，共用 CS（LED 驅動、移位暫存器）
3. CS 腳位不夠時用解碼器（74HC138）

### Q6. CAN 如何決定誰可以傳送？

CSMA/CR + 非破壞性位元仲裁：所有節點同時送出 ID，逐 bit 比較，顯性（0）蓋過隱性（1）；送出隱性卻讀到顯性的節點知道自己輸了，停止傳送並改為接收。結果：**ID 越小優先權越高**，且勝出的訊息完全不受延遲。

### Q7. CAN 為什麼需要 120Ω 終端電阻？

匹配雙絞線的特性阻抗（約 120Ω），避免訊號在線路末端反射；同時提供顯性/隱性狀態切換時的放電路徑。匯流排兩端各一顆，量測 CAN_H 與 CAN_L 之間應約 **60Ω**。

### Q8. CAN 與 CAN FD 差別？

資料長度 8 → 64 bytes；資料段可切換到更高速率（BRS）；CRC 加強。仲裁段速率不變以維持相容與距離。

### Q9. UART 115200 8N1 傳 1KB 需要多久？

每 byte 10 bit → 10240 bit / 115200 ≈ **89 ms**。

### Q10. CRC 與 Checksum 差在哪？CRC 能防止惡意竄改嗎？

CRC 偵錯能力遠強於簡單加總（能偵測位元交換、突發錯誤）。**不能防竄改**：CRC 是公開演算法，攻擊者可改資料後重新計算。防竄改需要 HMAC 或數位簽章。

### Q11. 如何設計一個可靠的 UART 通訊協定？

見第 9 節：起始碼 + 長度 + 命令 + 序號 + 資料 + CRC；接收端用狀態機解析並處理逾時；ACK/重傳；或採用 COBS 編碼簡化訊框。

## 過時技術（知道就好）

- **RS-232 DB9 接頭**：仍見於舊式工業設備，新設計多改用 USB-CDC 或 RS-485。
- **並列匯流排（並列 LCD、並列 Flash）**：被 SPI/QSPI/MIPI 取代。
- **Classical CAN 於新車款高頻寬應用**：逐漸被 CAN FD、CAN XL、車用乙太網路取代。

## 本章回顧

- UART：非同步、8N1、TX/RX 交叉、共地
- I²C：開汲極 + 上拉、位址 + ACK、會卡死要 9 個 clock 救
- SPI：四線、全雙工、CPOL/CPHA 四種模式、一裝置一 CS
- CAN：差動、ID 即優先權、非破壞仲裁、120Ω × 2
- CRC 防意外錯誤、簽章防竄改；自訂協定用狀態機解析
