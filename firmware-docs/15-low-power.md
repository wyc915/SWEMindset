# 15. 低功耗設計

> **一句話**：電池裝置的續航力 = **大部分時間睡覺、醒來快速做完、立刻再睡**。低功耗是韌體與硬體一起完成的系統工程。

---

## 1. 功耗基礎 🟢

```
動態功耗 P ≈ C × V² × f     （電容 × 電壓平方 × 頻率）
靜態功耗 = 漏電流 × V
```

- **降電壓**效果最大（平方關係）
- **降頻率**可降低動態功耗，但執行時間變長
- 溫度越高漏電流越大

### 1.1 電池壽命估算

```
平均電流 = (I_active × t_active + I_sleep × t_sleep) / 週期

例：每 10 秒醒來 10ms 量測並傳送
   I_active = 8mA、I_sleep = 2µA
   平均 ≈ (8mA × 0.01 + 0.002mA × 9.99) / 10 ≈ 0.01 mA = 10µA
   CR2032（約 220mAh）→ 220 / 0.01 ≈ 22,000 小時 ≈ 2.5 年（未計自放電與溫度）
```

**結論**：睡眠電流與喚醒頻率往往比執行時的電流更重要。

## 2. MCU 低功耗模式 🟡

以 STM32 為例（各家命名不同但概念相同）：

| 模式 | CPU | 時脈 | RAM | 喚醒來源 | 典型電流 | 喚醒時間 |
|---|---|---|---|---|---|---|
| Run | 運作 | 全開 | 保留 | — | mA 級 | — |
| **Sleep** | 停止 | 周邊運作 | 保留 | 任何中斷 | 降低 | 極快 |
| **Stop / Deep Sleep** | 停止 | 主時脈關閉 | 保留 | EXTI、RTC、LPUART | µA 級 | µs 級 |
| **Standby / Shutdown** | 關閉 | 只剩 RTC/喚醒電路 | **大部分遺失** | 喚醒腳位、RTC | nA ～ 數百 nA | 等同重置 |

Cortex-M 指令：
- `WFI`（Wait For Interrupt）、`WFE`（Wait For Event）
- `SCB->SCR` 的 **SLEEPDEEP** 位元選擇深度
- **Sleep-on-Exit**：ISR 結束後自動回到睡眠，適合完全中斷驅動的系統

## 3. 韌體省電技巧 🟡

| 類別 | 技巧 |
|---|---|
| **睡眠策略** | 閒置即睡；RTOS 使用 **Tickless Idle**；避免忙碌等待 |
| 時脈 | 用夠用的最低頻率；或「**Race to Sleep**」：全速做完立刻睡（通常更省） |
| 周邊 | **不用的周邊關時脈**；感測器用完進入 power-down |
| **GPIO** | 未使用腳位設為**類比模式**（避免浮接輸入漏電）；注意外部上拉/下拉造成的漏電 |
| 通訊 | 批次傳送（累積資料一次傳）；降低無線廣播頻率；縮短連線時間 |
| DMA | 讓 DMA 在 CPU 睡眠時搬資料 |
| 電源域 | 用 GPIO 或負載開關**切斷外部模組電源** |
| 硬體 | 低 Iq 的 LDO / DC-DC；高阻值分壓電阻（或可切斷）量電池 |
| 演算法 | 減少運算量、使用硬體加速器 |
| 除錯 | **量測時拔除除錯器**：除錯介面會阻止進入深度睡眠或增加耗電 |

## 4. 量測功耗 🟡

| 工具 | 特性 |
|---|---|
| 萬用電表 | 只能看平均值，無法捕捉 µs 級脈衝 |
| **Nordic Power Profiler Kit II（PPK2）** | 平價、µA～A 動態範圍、可視化波形，業界與自學常用 |
| **Joulescope** | 高精度、高動態範圍 |
| Otii Arc | 功耗分析 + 電池模擬 |
| STLINK-V3PWR、SEGGER 工具 | 原廠/除錯器整合 |

**分析步驟**：看到電流波形 → 對照韌體事件（GPIO 打點標記）→ 找出意外的高電流區段（沒睡下去、喚醒太頻繁、外部模組沒關）。

## 5. 低功耗無線 🟡

| 技術 | 功耗關鍵 |
|---|---|
| **BLE** | 廣播間隔、連線間隔（Connection Interval）、Slave Latency、TX 功率 |
| Wi-Fi | 耗電大；用 DTIM 省電模式、**Wi-Fi 6 TWT（Target Wake Time）**、或盡量短連線 |
| LoRaWAN | Class A 最省電（只在上傳後開兩個接收窗） |
| NB-IoT / LTE-M | **PSM、eDRX** 省電機制 |
| Thread | Sleepy End Device（SED/SSED） |

## 6. 能量採集（Energy Harvesting）🔴

太陽能、振動、熱電、RF 取電 → 搭配超級電容與專用 PMIC，可做到**免電池裝置**。韌體需設計成**隨時可能斷電**：狀態存在 FRAM/Flash、快速恢復（間歇運算 Intermittent Computing）。

## 面試常問

### Q1. 如何降低 MCU 功耗？

見第 3 節。依序回答：睡眠模式選擇 → 喚醒策略（中斷驅動、Tickless）→ 關閉不用的周邊與時脈 → GPIO 設定 → 降低無線活動 → 量測驗證。

### Q2. Sleep、Stop、Standby 的差別？

見第 2 節：越深越省電，但保留的狀態越少、喚醒越慢、喚醒來源越少。Standby 喚醒後等同重置，需從頭初始化（可用備份暫存器保存少量狀態）。

### Q3. 為什麼未使用的 GPIO 要設為類比模式？

浮接的數位輸入電位會在中間值游移，輸入緩衝器中的上下電晶體同時部分導通，產生漏電流（甚至振盪）。類比模式關閉數位輸入緩衝器，漏電流最低。

### Q4. 「Race to Sleep」是什麼？

以最高效能盡快完成工作，然後進入深度睡眠。因為 MCU 有固定的靜態功耗與周邊功耗，縮短清醒時間往往比降頻更省電。實際仍需量測確認。

### Q5. 估算電池壽命：每分鐘喚醒 50ms、耗電 10mA，睡眠 5µA，1000mAh 電池可用多久？

平均電流 = (10 × 0.05 + 0.005 × 59.95) / 60 ≈ (0.5 + 0.3) / 60 ≈ **0.0133 mA**。1000 / 0.0133 ≈ 75,000 小時 ≈ **8.5 年**（實際受自放電、溫度、電池內阻限制，通常會打折）。

### Q6. 為什麼接著除錯器量到的電流比較高？

除錯介面（SWD）會保持除錯電路與部分時脈運作，許多 MCU 在除錯連接時無法進入最深睡眠或會自動啟用 debug-in-low-power 設定。量測功耗時應斷開除錯器並完整重新上電。

## 過時技術（知道就好）

- **以降頻作為主要省電手段**：現代 MCU 深度睡眠電流極低，「快速做完去睡」通常更有效。
- **Bluetooth Classic 用於低功耗感測器**：已被 BLE 取代。

## 本章回顧

- 功耗 ∝ V² × f；平均電流由睡眠電流與喚醒頻率主導
- Sleep → Stop → Standby：越深越省、恢復越慢
- 關周邊時脈、GPIO 設類比、Tickless Idle
- 用 PPK2 / Joulescope 量測，量測時移除除錯器
