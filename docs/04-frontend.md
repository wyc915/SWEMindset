# 04. 前端開發

> **一句話**：前端的核心問題是「如何有效率地把資料變成畫面，並讓使用者覺得快」。

## 學習目標

- 描述瀏覽器渲染流程與框架「只更新必要部分」的原因
- 比較 CSR、SSR、SSG 並依情境選擇
- 判斷哪些狀態該放全域、哪些放元件內
- 用 Core Web Vitals 衡量並優化前端效能

---

## 1. 瀏覽器基本原理 🟢

- **三大基礎**：HTML（結構）、CSS（樣式）、JavaScript（行為）
- **渲染流程**：解析 HTML → 建立 DOM → 套用 CSS → 計算版面（Layout）→ 繪製（Paint）
  - 頻繁改 DOM 很慢 → 這就是 Vue / React 用「虛擬 DOM / 響應式更新」只改必要部分的原因
- **事件迴圈**：JS 是單執行緒，長時間運算會讓畫面卡住
- **RWD 響應式設計**：同一頁面適應手機與桌機（Flexbox、Grid）

## 2. 主流框架 🟢

| 框架 | 特色 | 全端框架 |
|---|---|---|
| **React** | 生態最大、職缺最多 | Next.js |
| **Vue** | 上手容易、文件友善 | Nuxt |
| **Angular** | 大而全、企業常用、強制 TypeScript | — |

> 三者觀念相通：**元件化、單向資料流、響應式狀態**。會一個，學另一個很快。

## 3. 渲染策略（面試熱點）🟡

| 策略 | 做法 | 優點 | 缺點 | 適合 |
|---|---|---|---|---|
| **CSR** 客戶端渲染 | 瀏覽器下載 JS 後產生畫面 | 互動流暢 | 首屏慢、SEO 差 | 後台系統 |
| **SSR** 伺服器渲染 | 伺服器產生 HTML 再送出 | 首屏快、SEO 好 | 伺服器負擔大 | 電商、內容網站 |
| **SSG** 靜態生成 | 建置時就產生 HTML | 最快、最便宜 | 內容更新需重建 | 部落格、文件站 |

- **Hydration**：SSR 送來的靜態 HTML，再由 JS「接手」變成可互動。

## 4. 狀態管理 🟡

- **元件內狀態**：只有自己用
- **全域狀態**（Pinia、Redux、Zustand）：登入資訊、購物車
- **伺服器狀態**（TanStack Query）：API 資料的快取、重新整理、載入狀態
- 原則：**不要什麼都丟全域**，能放元件內就放元件內

## 5. 建置工具 🟢

- **Vite**：現今主流，開發啟動極快
- 打包會做：合併檔案、壓縮、**Tree Shaking**（移除沒用到的程式碼）、**Code Splitting**（按頁面分批載入）

## 6. 效能與安全 🟡

**效能指標（Core Web Vitals）**：
- **LCP**：主要內容多快出現
- **INP**：操作後多快有反應
- **CLS**：畫面會不會亂跳

**常見優化**：圖片壓縮與延遲載入、CDN、快取、減少首屏 JS。

**前端安全**：
- **XSS**：惡意腳本注入頁面 → 框架預設會跳脫輸出，避免直接插入未處理的 HTML
- **CSRF**：冒用使用者身分發請求 → SameSite Cookie、CSRF Token
- Token 存放：HttpOnly Cookie 較能防 XSS 竊取

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. CSR、SSR、SSG 的差別與適用場景？

- **CSR**：瀏覽器下載 JS 後才產生畫面。首屏慢、SEO 差，但後續互動流暢 → **後台管理系統、需登入的應用**
- **SSR**：每次請求由伺服器產生 HTML。首屏快、SEO 好，但伺服器負擔大 → **電商、新聞等內容常變動且需 SEO 的網站**
- **SSG**：建置時就產生好 HTML。最快、最便宜、可放 CDN，但內容更新需重新建置 → **部落格、文件站**（本知識庫就是 SSG）

現代框架（Nuxt、Next.js）可以在同一個專案中針對不同頁面混用。

### Q2. Vue 的響應式原理大致是怎樣？

Vue 3 使用 **Proxy** 包裝資料物件：
1. **收集依賴**：元件渲染時讀取了哪些資料，Vue 就記錄「這個元件依賴這些資料」
2. **觸發更新**：資料被修改時，Proxy 攔截到寫入，通知依賴它的元件重新渲染
3. 重新渲染時透過**虛擬 DOM 比對差異**，只更新真正變動的 DOM

（Vue 2 使用 `Object.defineProperty`，無法偵測新增屬性與陣列索引修改，是 Vue 3 改用 Proxy 的原因之一。）

### Q3. 如何優化首頁載入速度？

從「少載、快載、晚載」三方向：
- **減少資源大小**：壓縮 JS / CSS、Tree Shaking、圖片改用 WebP / AVIF 並依螢幕給適當尺寸
- **拆分與延遲載入**：Code Splitting 依路由分批載入、圖片與非首屏元件 Lazy Load
- **加快傳輸**：CDN、HTTP 快取標頭、HTTP/2 或 HTTP/3、預先連線（preconnect）
- **改變渲染方式**：首屏改用 SSR / SSG
- **量測**：用 Lighthouse 看 LCP、INP、CLS，找出真正的瓶頸再優化

### Q4. XSS 與 CSRF 差在哪？怎麼防？

- **XSS（跨站腳本）**：攻擊者把**惡意腳本注入到你的網頁**，在其他使用者的瀏覽器執行，可竊取資料或冒用操作
  - 防：輸出時跳脫（Vue/React 預設會做，避免 `v-html` 放未過濾內容）、設定 CSP、Cookie 加 HttpOnly
- **CSRF（跨站請求偽造）**：使用者已登入你的網站，**在惡意網站被誘導送出請求**，瀏覽器自動帶上 Cookie
  - 防：Cookie 設 `SameSite=Lax/Strict`、CSRF Token、重要操作再次驗證

差異：XSS 是「在你的網站上執行壞程式」；CSRF 是「從別的網站借用你的登入身分」。

### Q5. 什麼時候需要全域狀態管理？

當**多個不相鄰的元件需要共用並修改同一份資料**時，例如：登入使用者資訊、購物車、主題設定、多步驟表單的跨頁資料。

不需要的情況：
- 只有一個元件使用 → 放元件內
- 父子元件傳遞 → 用 props / emit
- **來自 API 的資料** → 優先用 TanStack Query 等伺服器狀態工具處理快取與重新整理，而不是全部塞進 Pinia / Redux

原則：全域狀態越少越好，否則資料流難以追蹤。
