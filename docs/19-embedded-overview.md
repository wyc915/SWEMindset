# 19. 嵌入式與韌體總覽（轉職橋接）

> **一句話**：韌體是「直接控制硬體的軟體」。最大差異在於**資源極少、時間要準、出錯可能燒壞硬體或無法遠端修復**。

## 學習目標

- 說出韌體開發與一般軟體開發的關鍵差異
- 分辨 MCU 與 MPU，並判斷產品該用裸機、RTOS 或嵌入式 Linux
- 了解台灣韌體職缺的主要產業與各自需要的技能
- 規劃自己的韌體學習路線（第 20～25 章）

---

## 1. 軟體 vs 韌體思維差異 🟢

| 面向 | 一般軟體 | 韌體 |
|---|---|---|
| 資源 | GB 等級記憶體 | KB～MB 等級 |
| 作業系統 | Windows / Linux | 無（裸機）、RTOS、或嵌入式 Linux |
| 時間要求 | 慢一點沒關係 | 常要求**在固定時間內必定完成**（即時性） |
| 出錯代價 | 重新部署 | 裝置變磚、硬體損壞、安全事故 |
| 除錯方式 | 中斷點、Log | 除錯器、示波器、邏輯分析儀 |
| 更新 | 隨時部署 | OTA 或實體燒錄，需非常謹慎 |
| 問題來源 | 只有軟體 | **軟體、硬體、電源、雜訊都可能**，要能分辨 |

## 2. 硬體平台怎麼選 🟢

### 2.1 MCU vs MPU

| | MCU（微控制器） | MPU（微處理器） |
|---|---|---|
| 特性 | 單一晶片內含 CPU、Flash、RAM、周邊 | 需外接 DRAM 與儲存 |
| 系統 | 裸機或 RTOS | 通常跑 Linux |
| 例子 | STM32、ESP32、nRF52、新唐 NuMicro | NXP i.MX、TI Sitara、樹莓派 |
| 用途 | 感測器、家電、穿戴裝置、馬達控制 | 閘道器、工控面板、車機、網通設備 |

### 2.2 處理器架構

- **ARM Cortex-M**：MCU 主流（M0+ 低成本、M4/M7 有浮點與 DSP、M33 有 TrustZone 安全功能）
- **ARM Cortex-A**：手機、嵌入式 Linux
- **RISC-V**：開源指令集，MCU 與 IC 內部控制核心快速採用
- **8051**：1980 年代的 8 位元架構，**仍大量存在**於低成本 MCU、觸控 IC、電源 IC、筆電 EC 中

### 2.3 軟體架構：裸機、RTOS、Linux

| 架構 | 適合 | 特性 |
|---|---|---|
| **裸機 Super Loop**（主迴圈 + 中斷） | 功能單純、成本敏感、需要最可預測的時序 | 最簡單、最省資源、最容易驗證 |
| **RTOS** | 多個任務、各有不同時序需求、需要網路堆疊或 USB | 任務切分清楚、即時性佳 |
| **嵌入式 Linux** | 需要複雜網路、檔案系統、圖形介面、豐富套件 | 功能強大，但開機慢、資源需求高、即時性較弱 |

> **重點**：Super Loop 不是「過時」，而是一個合理的設計選擇。架構應依需求選擇，不是越複雜越好。

**建議實作路線**（作品集）：
```
STM32 Nucleo 或 ESP32 開發板
  → 裸機：GPIO、UART 輸出、按鍵中斷
  → 周邊：I²C / SPI 讀取溫溼度感測器、Timer 產生 PWM
  → 導入 FreeRTOS：拆成感測、通訊、顯示任務
  → MQTT 上傳到雲端（可用你熟悉的 Node.js / .NET 做後台）
  → 實作 OTA 更新與看門狗
  → 加入單元測試與 GitHub Actions 自動建置
  → 整理成 GitHub 作品集與說明文件
```

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. MCU 與 MPU 的差別？

- **MCU（微控制器）**：單一晶片整合 CPU、Flash、RAM 與周邊（GPIO、UART、ADC…）。資源小（KB～MB）、功耗低、成本低、啟動快、即時性好，通常跑**裸機或 RTOS**。例：STM32、ESP32、nRF52。適合感測器、家電、穿戴裝置。
- **MPU（微處理器）**：只有運算核心，需外接 DRAM 與儲存裝置，效能強、通常有 MMU，可跑 **Linux** 等完整作業系統。例：NXP i.MX、樹莓派的處理器。適合閘道器、HMI 面板、車機。

選擇依據：是否需要複雜功能（網路堆疊、圖形介面、檔案系統）、即時性需求、功耗與成本。

### Q2. 裸機、RTOS、嵌入式 Linux 怎麼選？

- **裸機**：功能少、成本與功耗極敏感、需要最可預測的時序。例：遙控器、簡單感測器。
- **RTOS**：多個功能需要並行且各有時序要求，或需要網路、USB、檔案系統等中介軟體，但仍要即時反應與低功耗。例：智慧家電、穿戴裝置、工業感測器。
- **嵌入式 Linux**：需要完整網路功能、圖形介面、大量現成套件或多種程式語言，可接受較長開機時間與較高成本。例：路由器、閘道器、車機、BMC。

判斷順序：功能複雜度 → 即時性需求 → 成本與功耗 → 團隊能力與既有程式碼。

### Q3. 韌體開發與一般軟體開發最大的差異是什麼？

- **資源受限**：記憶體以 KB 計，需要精打細算，避免動態配置
- **即時性**：某些工作必須在固定時間內完成，錯過就是錯誤
- **與硬體緊密耦合**：問題可能來自硬體、電源、雜訊，需會用量測工具判斷
- **更新困難**：裝置在客戶端，更新失敗可能變磚，必須設計安全的更新機制
- **可靠性要求高**：裝置可能連續運作數年、無人看管，需要看門狗與錯誤復原

### Q4. 為什麼想從軟體轉韌體？（行為題）

沒有標準答案，建議結構：
1. **動機**：對硬體與軟體結合的興趣，例如想看到程式直接控制實體裝置
2. **已有的準備**：自學 C、完成哪些開發板專案（拿出 GitHub 作品集）
3. **能帶來的價值**：CI/CD、自動化測試、雲端串接、Linux 與 API 設計經驗
4. **長期目標**：例如往 IoT 平台、BMC 或嵌入式 Linux 發展

避免只說「韌體比較穩定」或「薪水較高」，要展現具體行動與熱情。

## 常見誤解

- **「8051 已經淘汰」**：架構老舊，但仍大量用於低成本 MCU（例如新唐 N76E003）、觸控 IC、電源 IC 與筆電 EC。新設計多選 Cortex-M0+ 或 RISC-V，但面試與維護舊產品時仍可能遇到。
- **「Super Loop 已經過時」**：在功能單純的產品中，Super Loop 簡單、可預測、易驗證，是正確選擇。功能變多、時序需求不同時才需要 RTOS。
- **「韌體不用寫測試」**：現代韌體團隊越來越重視單元測試、CI 與 HIL 自動化測試，這正是軟體背景的優勢（[第 23 章](23-firmware-debug-test-release.md)）。

## 本章回顧

- 韌體 = 資源少、時間準、出錯代價高
- 架構依需求選：裸機、RTOS、Linux 各有適用場景
- 台灣的伺服器 BMC、網通、IoT 領域對軟體背景特別友善
