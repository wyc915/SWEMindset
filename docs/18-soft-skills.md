# 18. 軟技能與職涯

> **一句話**：技術決定你能不能做，軟技能決定你能做到多大。資深工程師的價值在於「做對的事」，而不只是「把事做對」。

---

## 1. 溝通 🟢

- **先講結論，再講細節**：主管與跨部門最常問「所以會不會延期？」
- **把技術轉成影響**：不說「要重構資料存取層」，而說「重構後新功能開發時間可減少三成」
- **主動回報風險**：越早說，越有調整空間；最後一天才說延期最傷信任
- **書面溝通**：寫清楚的 PR 說明、技術文件與會議紀錄

## 2. 需求釐清 🟢

動手前先確認：
- **要解決什麼問題？** 使用者真正需要的可能不是他說的功能
- **成功的標準是什麼？**
- **非功能需求**：要多快？多少人同時用？資料保存多久？
- **範疇**：這次不做什麼

## 3. 技術決策 🟡

1. 列出 2～3 個可行選項
2. 比較優缺點、成本、風險
3. 選擇並說明理由
4. 用 **ADR（架構決策紀錄）** 寫下來

> 「它很潮」不是理由；「它解決我們的 X 問題，代價是 Y，我們可以接受」才是。

## 4. 工作方法 🟢

- **拆解任務**：大任務拆成一天內可完成的小任務，進度才看得見
- **估算**：加上緩衝，考慮測試、Code Review 與部署時間
- **優先順序**：重要且緊急先做；重要不緊急要排時間做（例如技術債）
- **卡住超過一定時間就求助**：自己硬撐不是美德

## 5. 持續學習 🟢

- 讀**官方文件**優先於二手教學文章
- 學一個技術時，先問「它在解決什麼問題？」（本知識庫的核心精神）
- **動手做專案**比看教學影片有效
- 追蹤業界趨勢：技術雷達（ThoughtWorks Technology Radar）、各技術官方部落格

## 6. 職級能力對照 🟡

| 職級 | 能力特徵 |
|---|---|
| 🟢 初階 | 在指導下完成明確任務，熟悉團隊工具與流程 |
| 🟡 中階 | 獨立負責一個功能或模組，考慮測試、效能與維運 |
| 🔴 資深 | 設計系統、做技術決策、影響跨團隊、指導他人 |
| 🔴 主任 / 架構師 | 制定技術方向，平衡商業目標與技術品質 |

## 7. 面試準備 🟢

| 類型 | 準備方式 |
|---|---|
| 技術觀念 | 本知識庫各章「面試常問」 |
| 系統設計 | 第 19 章的框架 |
| 專案經驗 | 用 **STAR** 結構：情境（Situation）→ 任務（Task）→ 行動（Action）→ 結果（Result），盡量量化結果 |
| 行為面試 | 衝突處理、失敗經驗、學習新技術的經驗 |
| 反問面試官 | 團隊開發流程、技術債狀況、部署頻率、On-call 制度 |

**轉職者特別準備**：說明「為什麼轉換」與「既有經驗如何帶來價值」，並以**實作作品集**證明學習成果。

---

## 本章回顧

- 先講結論、主動報風險
- 決策要有選項、取捨與紀錄
- 專案經驗用 STAR 講，結果要量化
