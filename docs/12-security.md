# 12. 資訊安全

> **一句話**：安全不是最後再加的功能，而是每一行程式的預設習慣。多數漏洞來自「相信了不該相信的輸入」。

---

## 1. 最常見的攻擊與防禦 🟢

| 攻擊 | 怎麼發生 | 防禦 |
|---|---|---|
| **SQL Injection** | 把使用者輸入直接拼接進 SQL | **參數化查詢**（ORM 預設就是），永不字串拼接 |
| **XSS 跨站腳本** | 使用者輸入的腳本被顯示在別人的頁面上執行 | 輸出跳脫（框架預設會做）、CSP 標頭 |
| **CSRF 跨站請求偽造** | 惡意網站利用你已登入的 Cookie 發送請求 | SameSite Cookie、CSRF Token |
| **權限失效（IDOR）** | 把網址 `/orders/123` 改成 `/orders/124` 就看到別人資料 | **每個請求都在後端檢查擁有權**，不能只靠前端隱藏 |
| **敏感資料外洩** | 密碼明碼、Log 印出個資、錯誤訊息洩漏內部資訊 | 加密、遮罩、統一錯誤訊息 |
| **SSRF** | 讓伺服器去請求攻擊者指定的內部網址 | 白名單限制可存取的目標 |

> **OWASP Top 10** 是業界最常引用的 Web 風險清單，2025 版第一名為「存取控制失效」。

## 2. 密碼與加密觀念 🟢

| 觀念 | 重點 |
|---|---|
| **雜湊 ≠ 加密** | 雜湊不可逆（存密碼用）；加密可解密（存需要還原的資料用） |
| **密碼儲存** | 用 **Argon2id / bcrypt / PBKDF2**（刻意設計成慢）+ Salt；**不要用 MD5、SHA-1，也不要直接用 SHA-256** |
| **對稱加密** | 同一把金鑰加解密，快（AES） |
| **非對稱加密** | 公鑰加密、私鑰解密，或私鑰簽章、公鑰驗證（RSA、ECC）；HTTPS 用它來交換對稱金鑰 |
| **數位簽章** | 證明「是我發的」且「沒被改過」，例：JWT、軟體更新、韌體驗證 |

## 3. 開發時的安全習慣 🟡

- **最小權限**：資料庫帳號、雲端權限、服務帳號只給必要的權限
- **機密不進 Git**：密碼、API Key 放在環境變數或機密管理服務（Azure Key Vault、AWS Secrets Manager、HashiCorp Vault）
- **全站 HTTPS**，使用 TLS 1.2 以上
- **輸入驗證在後端**：前端驗證只是使用者體驗，攻擊者可以直接呼叫 API
- **Log 不記錄敏感資料**：密碼、完整卡號、Token
- **相依套件定期更新**：多數漏洞來自第三方套件

## 4. 軟體供應鏈安全 🟡

近年最受重視的領域：攻擊者不打你，而是汙染你用的套件。

- **相依套件掃描（SCA）**：Dependabot、Snyk 自動通知有漏洞的套件
- **靜態程式碼掃描（SAST）**：在 CI 中自動找出常見漏洞寫法
- **機密掃描**：防止不小心把金鑰 commit 進去
- **容器映像掃描**：Trivy 等工具
- **SBOM（軟體物料清單）**：列出產品用了哪些元件，歐盟《網路韌性法案》（CRA）等法規逐步要求

## 5. 零信任（Zero Trust）🔴

傳統觀念：公司內網是安全的。
零信任：**不信任任何網路位置，每個請求都要驗證身分與權限**。服務之間也要認證（如 mTLS）。

## 過時技術（知道就好）

- **MD5、SHA-1、DES、3DES**：已不安全，不可用於密碼或簽章。
- **SSL、TLS 1.0 / 1.1**：已淘汰。
- **把密碼寫在 Web.config / appsettings.json 並提交到版控**：舊專案常見的壞習慣。

## 本章回顧

- 不信任任何輸入，權限一律後端檢查
- 密碼用 Argon2id / bcrypt，機密不進 Git
- 套件也是攻擊面，交給 CI 自動掃描
