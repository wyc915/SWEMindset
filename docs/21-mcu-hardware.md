# 21. MCU 硬體與周邊

> **一句話**：韌體工程師不用會設計電路，但必須**看得懂 Datasheet 與電路圖，知道訊號在線上長什麼樣子**，否則無法判斷問題出在軟體還是硬體。

## 學習目標

- 理解邏輯電位、上拉 / 下拉電阻、推挽與開汲極輸出
- 知道 Datasheet、Reference Manual、Errata 分別要查什麼
- 會設定 GPIO、Timer / PWM、ADC，並理解時脈與 DMA 的角色
- 比較 UART、I²C、SPI、CAN 的特性與使用時機

---

## 1. 最低限度的電子學 🟢

| 觀念 | 白話 | 為什麼重要 |
|---|---|---|
| **電壓、電流、電阻** | 歐姆定律 V = I × R | 估算 LED 限流電阻、腳位能輸出多少電流 |
| **邏輯電位** | 3.3V 系統：約 0V 為 0、約 3.3V 為 1 | **3.3V 與 5V 裝置直接相接可能燒壞晶片**，需要電位轉換 |
| **共地（GND）** | 兩個裝置通訊時必須接在同一個地 | 沒共地是通訊失敗的常見原因 |
| **上拉 / 下拉電阻** | 腳位沒被驅動時，讓它穩定在高或低電位 | 避免「浮接」造成隨機讀值 |
| **推挽（Push-Pull）輸出** | 能主動輸出高與低 | 一般 GPIO 輸出 |
| **開汲極（Open-Drain）輸出** | 只能拉低，高電位靠上拉電阻 | 多個裝置共用一條線（I²C）不會短路 |

**電源與雜訊**：電壓不穩、地線設計不良、馬達干擾，都會造成看似「軟體 bug」的隨機問題。

## 2. 怎麼讀晶片文件 🟢

| 文件 | 查什麼 |
|---|---|
| **Datasheet（規格書）** | 腳位定義、電氣特性（電壓範圍、電流上限）、時序參數、封裝 |
| **Reference Manual（參考手冊）** | **每個周邊的暫存器**與使用方式，韌體工程師最常翻的文件 |
| **Errata（勘誤表）** | **晶片已知的硬體 bug** 與替代做法——怪問題找不到原因時先查這份 |
| **Application Note** | 晶片廠提供的特定應用範例與設計建議 |
| **電路圖（Schematic）** | 哪個腳位接到哪個元件、有無上拉電阻、電源架構 |

閱讀技巧：先看**方塊圖**掌握全貌，再查需要的周邊章節；不需要從頭讀到尾。

## 3. 時脈 🟡

- 時脈來源：內部 RC 振盪器（方便但較不準）、外部晶振（準確）、**PLL**（倍頻到更高速度）
- **時脈樹**：系統時脈再分配給各匯流排與周邊
- **每個周邊使用前都要開啟它的時脈**——「設定了暫存器卻沒反應」最常見的原因就是忘了開時脈
- 時脈越高越耗電，低功耗設計會動態調整

## 4. GPIO 🟢

- 模式：輸入、輸出、**複用功能（Alternate Function，交給 UART / SPI 等周邊使用）**、類比
- 輸入可設定上拉 / 下拉；輸出可設定推挽 / 開汲極與速度
- **按鍵去彈跳（Debounce）**：機械按鍵按下時會在幾毫秒內快速抖動，造成多次觸發
  - 硬體：RC 濾波電路
  - 軟體：偵測到變化後等待約 10～50ms 再確認狀態，或定時取樣連續多次相同才算數

## 5. Timer 與 PWM 🟡

Timer 是 MCU 最常用的周邊之一：
- **定時中斷**：每 1ms 觸發一次，作為系統時基
- **PWM（脈衝寬度調變）**：固定頻率下調整高電位時間比例（**占空比**），用於 LED 亮度、馬達速度、蜂鳴器
- **輸入捕捉**：量測外部訊號的頻率或脈寬（例如超音波測距、轉速）
- **輸出比較**：在精確時間點觸發動作

## 6. ADC 與 DAC 🟡

- **ADC**：把類比電壓轉成數字。**解析度** 12 位元 = 4096 級，參考電壓 3.3V 時每級約 0.8mV
- **取樣率**：每秒取樣次數，依訊號變化速度決定
- 實務：讀值會有雜訊 → **多次取樣平均**、軟體濾波；量測電壓超過參考電壓要先分壓
- **DAC**：把數字轉成類比電壓（音訊、波形產生）

## 7. 通訊介面（面試必考）🟡

| 介面 | 線數 | 特性 | 常見用途 |
|---|---|---|---|
| **UART** | 2（TX、RX） | 非同步，雙方約定鮑率（如 115200）、格式（常見 8N1） | 除錯輸出、GPS、模組通訊 |
| **I²C** | 2（SDA、SCL） | 同步、開汲極需**上拉電阻**、以**位址**區分多個裝置、半雙工 | 感測器、EEPROM |
| **SPI** | 4（SCK、MOSI、MISO、CS） | 同步、全雙工、速度快，每個裝置一條 **CS** 線，有 4 種時脈模式 | 顯示器、Flash、SD 卡 |
| **CAN** | 2（差動 CAN_H、CAN_L） | 抗干擾、多節點、依 **ID 仲裁優先權**，兩端需 120Ω 終端電阻 | 汽車、工業設備 |
| **USB** | — | 高速、協定複雜，通常使用晶片廠的協定堆疊 | 電腦連接 |
| **乙太網路** | — | 需要 TCP/IP 協定堆疊（如 lwIP） | 工控、網通 |

**實體層補充**：UART 是「邏輯協定」，實際線路可能是 TTL 電位、**RS-232**（電腦序列埠）或 **RS-485**（差動、長距離、多點，工業常見，常搭配 **Modbus** 協定）。

**無線**：BLE（低功耗藍牙）、Wi-Fi、LoRa（長距離低功耗）、Thread / Matter（智慧家庭統一標準）、Cellular IoT（NB-IoT、LTE-M）。

**IoT 應用層**：**MQTT** 是輕量的發佈 / 訂閱協定，觀念與[第 08 章](08-message-queue.md)的訊息佇列相同；QoS 0/1/2 對應最多一次、至少一次、剛好一次。

## 8. DMA 🟡

**DMA（直接記憶體存取）**：由硬體在周邊與記憶體間搬資料，CPU 只需在開始與結束時處理。
- 用途：UART 大量收發、ADC 連續取樣、SPI 傳輸顯示資料
- 好處：CPU 可做其他事或進入睡眠，省電又高效
- 注意：有資料快取（Cache）的 MCU（如 Cortex-M7）要處理**快取一致性**，否則 CPU 可能讀到舊資料

## 9. Flash 與非揮發性儲存 🟡

| 特性 | 說明 |
|---|---|
| 抹除單位 | Flash 必須先以**區塊（Sector / Page）抹除**才能寫入，不能直接覆寫單一位元組 |
| 寫入壽命 | 每個區塊約可抹寫 1 萬～10 萬次 |
| **EEPROM 模擬** | 用 Flash 模擬可逐位元組更新的儲存，並分散寫入位置 |
| **磨耗平均（Wear Leveling）** | 把寫入平均分散到不同區塊，延長壽命 |

**NOR vs NAND Flash**：
- **NOR**：可直接隨機讀取、可原地執行程式（XIP），容量小、價格高 → 存放程式碼
- **NAND**：容量大、便宜、寫入快，但有壞區塊、需錯誤更正（ECC）→ 大量資料、Linux 檔案系統（eMMC、SSD 內部也是 NAND）

## 10. 低功耗 🟡

- 睡眠模式由淺到深：**Sleep → Stop → Standby**，越深越省電，但喚醒越慢、保留的狀態越少
- **喚醒來源**：外部中斷、RTC 計時器、通訊事件
- 原則：**盡快做完事、盡快睡**；關閉不用的周邊時脈；腳位設成適當狀態避免漏電
- 量測工具：電流計、專用功耗分析儀

## 動手練習

1. **GPIO 與去彈跳**：按鍵控制 LED，先不做去彈跳觀察誤觸發，再加入軟體去彈跳比較差異。
2. **PWM 呼吸燈**：用 Timer 產生 PWM，讓 LED 亮度漸亮漸暗。
3. **I²C 感測器**：讀取溫溼度感測器（如 SHT3x 或 BME280），用 UART 每秒印出數值。
4. **用邏輯分析儀看訊號**：買一台入門款邏輯分析儀，抓 UART 與 I²C 波形，對照 Datasheet 時序圖解讀。

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. UART、I²C、SPI 的差別？

| | UART | I²C | SPI |
|---|---|---|---|
| 線數 | 2（TX、RX） | 2（SDA 資料、SCL 時脈） | 4（MOSI、MISO、SCK、CS） |
| 同步 | 非同步（雙方約定鮑率） | 同步 | 同步 |
| 多裝置 | 點對點 | 一條匯流排掛多個裝置，用**位址**區分 | 每個裝置需要一條**CS 選擇線** |
| 速度 | 慢 | 中（常見 100k / 400kHz） | 快（數 MHz 至數十 MHz） |
| 雙工 | 全雙工 | 半雙工 | 全雙工 |
| 用途 | 除錯輸出、GPS、模組通訊 | 感測器、EEPROM | 顯示器、Flash、SD 卡 |

選擇原則：腳位少、裝置多、速度不高 → I²C；要求高速 → SPI；簡單點對點 → UART。

### Q2. I²C 為什麼需要上拉電阻？

I²C 的 SDA 與 SCL 使用**開汲極（Open-Drain）**輸出：每個裝置只能把線**拉低**，不能主動輸出高電位。沒有裝置拉低時，靠**上拉電阻**把線拉回高電位。

這樣設計的好處：多個裝置共用同一條線時，即使同時有人輸出高、有人輸出低也**不會短路**，並可實現 ACK 回應、時脈延展（Clock Stretching）與多主機仲裁。

電阻值常見 2.2k～10kΩ：太大會讓上升邊緣太慢、高速時通訊失敗；太小則耗電且可能超過腳位電流上限。

### Q3. SPI 的四種模式是什麼？

由兩個參數組成：
- **CPOL（時脈極性）**：閒置時時脈為低（0）或高（1）
- **CPHA（時脈相位）**：在時脈的第一個邊緣（0）或第二個邊緣（1）取樣資料

組合出 Mode 0～3，主機與從機的模式**必須一致**，否則讀到的資料會錯位。最常見的是 Mode 0（CPOL=0、CPHA=0）。設定前一定要查從機 Datasheet 的時序圖。

### Q4. CAN 匯流排如何決定誰先傳送？

CAN 使用**逐位元仲裁**：多個節點同時開始傳送時，一邊送 ID 一邊監聽匯流排。匯流排上「顯性位元（0）」會壓過「隱性位元（1）」，送出 1 卻聽到 0 的節點就知道自己輸了，立即停止傳送並稍後重試。

結果：**ID 數值越小優先權越高**，而且仲裁過程**不會破壞**勝出者的訊息（非破壞性仲裁），因此適合需要確定性與優先權的車用與工業環境。

### Q5. 周邊設定好了卻沒有反應，你會怎麼排查？

1. **周邊時脈有沒有開啟**（最常見）
2. **GPIO 腳位複用**是否設成該周邊的功能、腳位編號是否正確
3. 對照 Reference Manual 檢查**暫存器設定順序**（有些要先關閉周邊才能設定）
4. 用除錯器**讀回暫存器**確認值真的寫進去
5. 中斷相關：周邊中斷致能、NVIC 致能、中斷處理函式名稱是否與向量表一致
6. 硬體：電源、接線、共地、上拉電阻，用示波器或邏輯分析儀確認是否有訊號
7. 查 **Errata** 看是否為已知晶片問題

### Q6. 機械按鍵為什麼要去彈跳？怎麼做？

機械接點閉合或分開時會在幾毫秒內**快速抖動**，MCU 會讀到多次高低變化，造成一次按壓被判斷成多次。

做法：
- **硬體**：RC 低通濾波，必要時加史密特觸發器
- **軟體**：偵測到變化後等待 10～50ms 再讀一次確認；或用定時中斷每數毫秒取樣，連續多次相同才更新狀態
- 避免在中斷中用延遲等待，應交給計時器或主迴圈處理

### Q7. 12 位元 ADC、參考電壓 3.3V，讀到 2048 代表多少電壓？

每一級約為 3.3V ÷ 4096 ≈ **0.806mV**，讀值 2048 約為 2048 × 0.806mV ≈ **1.65V**（約參考電壓的一半）。

延伸：
- 要量測超過 3.3V 的電壓需先用電阻分壓
- 讀值有雜訊時用多次取樣平均或濾波
- 參考電壓本身不準會直接影響量測精度

### Q8. NOR Flash 和 NAND Flash 的差別？

| | NOR | NAND |
|---|---|---|
| 讀取 | 可隨機存取，可**原地執行程式（XIP）** | 以頁為單位讀取，不能直接執行 |
| 容量 / 價格 | 小、每 GB 較貴 | 大、便宜 |
| 寫入 / 抹除 | 較慢 | 較快 |
| 可靠性 | 高 | 有壞區塊，需要 **ECC** 與壞區塊管理 |
| 用途 | MCU 內建 Flash、存放開機程式 | eMMC、SSD、Linux 檔案系統 |

兩者都要**先抹除再寫入**，且抹寫次數有限，需要磨耗平均。

### Q9. 什麼是 DMA？使用時要注意什麼？

DMA 讓硬體直接在周邊與記憶體之間搬資料，不需要 CPU 逐位元組處理，適合大量或連續的資料傳輸（UART、ADC、SPI）。

注意事項：
- **緩衝區在傳輸期間不能被程式修改或釋放**，常用雙緩衝（Ping-Pong）交替使用
- 有資料快取的 MCU 需要在傳輸前後**清除或無效化快取**，否則會讀到舊資料
- 緩衝區要放在 DMA 可存取的記憶體區域，並注意對齊
- 處理傳輸完成與錯誤中斷

## 常見誤解

- **「3.3V 和 5V 裝置可以直接接」**：部分腳位能容忍 5V（5V tolerant），但必須查 Datasheet 確認；否則需要電位轉換。
- **「讀值不穩是程式問題」**：浮接的輸入腳、沒有共地、電源雜訊都會造成隨機讀值，先用量測工具確認硬體。

## 本章回顧

- 先開時脈、再設腳位複用、最後設定周邊
- I²C 靠開汲極與上拉電阻，SPI 快但腳位多，CAN 用 ID 仲裁優先權
- Datasheet 看電氣特性、Reference Manual 看暫存器、Errata 看晶片 bug
