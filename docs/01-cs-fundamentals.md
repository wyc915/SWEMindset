# 01. 電腦科學基礎

> **一句話**：所有效能問題、併發 bug、網路異常，最後都會追到這一章。不用背細節，但要懂「為什麼」。

---

## 1. 行程、執行緒、協程 🟢

| | 行程（Process） | 執行緒（Thread） | 協程（Coroutine / async） |
|---|---|---|---|
| 是什麼 | 一個執行中的程式 | 行程裡的執行單位 | 由程式自己排程的輕量任務 |
| 記憶體 | 各自獨立 | 共享同一行程 | 共享 |
| 切換成本 | 高 | 中 | 很低 |
| 例子 | 開兩個瀏覽器視窗 | 一個 Web Server 同時處理多個請求 | C# `async/await`、Go goroutine |

**重點**：執行緒共享記憶體 → 快，但兩個執行緒同時改同一變數就會出錯（Race Condition），所以需要「鎖」。

## 2. 同步與死結 🟢

- **Mutex（互斥鎖）**：同一時間只讓一個人進去。
- **Semaphore（號誌）**：同一時間最多 N 個人進去（例如限制同時連線數）。
- **死結（Deadlock）**：A 拿著鎖 1 等鎖 2，B 拿著鎖 2 等鎖 1，永遠卡住。
  - 預防最實用的方法：**所有人都按相同順序取鎖**，並設定逾時。

## 3. 記憶體：Stack vs Heap 🟢

| | Stack | Heap |
|---|---|---|
| 存什麼 | 區域變數、函式呼叫 | 動態建立的物件 |
| 管理 | 自動（函式結束就釋放） | 手動釋放或由 GC 回收 |
| 速度 | 快 | 較慢 |
| 常見問題 | Stack Overflow（遞迴太深） | 記憶體洩漏 |

**GC（垃圾回收）**：C#、Java、Go 自動回收不用的物件，代價是偶爾的暫停。韌體通常不用 GC，因為需要可預測的時間。

## 4. I/O 模型：為什麼 Node.js 能撐高併發 🟡

- **阻塞 I/O**：一個請求等資料庫時，執行緒就閒置卡住。一萬個請求要一萬個執行緒，記憶體會爆。
- **非阻塞 / 事件驅動 I/O**：發出請求後先去做別的事，資料回來時作業系統通知你（Linux 的 `epoll`、Windows 的 `IOCP`）。
- **結論**：Node.js、Nginx、C# async 都靠這機制，少量執行緒就能處理大量 I/O 等待。但 **CPU 密集運算不適合**，會卡住事件迴圈。

## 5. 數值與編碼常識 🟢

- **浮點數有誤差**：`0.1 + 0.2 ≠ 0.3`。**金額一律用 decimal 或整數（以分為單位）**。
- **UTF-8**：現今主流編碼，英文 1 byte、中文 3 bytes。亂碼通常是編碼不一致。
- **位元組序（Endian）**：多位元組資料的排列順序。網路傳輸、韌體通訊常需轉換。

## 6. 網路 🟢→🟡

### 6.1 一個網址輸入後發生什麼（面試經典）

1. **DNS 解析**：網域名稱 → IP 位址
2. **TCP 連線**：三次握手建立連線
3. **TLS 握手**：驗證憑證、協商加密（HTTPS）
4. **送出 HTTP 請求**，伺服器回應
5. 瀏覽器**解析並渲染**頁面

### 6.2 TCP vs UDP

| | TCP | UDP |
|---|---|---|
| 特性 | 可靠、有序、有連線 | 不保證送達、無連線 |
| 速度 | 較慢 | 快 |
| 用途 | 網頁、API、資料庫 | 影音串流、遊戲、DNS、HTTP/3 |

### 6.3 HTTP 必懂

- **方法**：GET（查）、POST（新增）、PUT（整筆更新）、PATCH（部分更新）、DELETE（刪除）
- **狀態碼**：`2xx` 成功、`3xx` 重新導向、`4xx` 客戶端錯（401 未登入、403 無權限、404 找不到、429 太頻繁）、`5xx` 伺服器錯（500 內部錯誤、502/503/504 閘道或服務不可用）
- **版本演進**：HTTP/1.1（一條連線一次一個請求）→ HTTP/2（一條連線並行多個請求）→ HTTP/3（改走 UDP 的 QUIC，弱網更穩）
- **HTTPS = HTTP + TLS**：防竊聽、防竄改、驗證對方身分。

### 6.4 其他常見名詞

- **反向代理**（Nginx）：擋在伺服器前面，負責轉發、負載平衡、HTTPS 終止。
- **CDN**：把靜態檔放到離使用者近的節點。
- **CORS**：瀏覽器限制跨網域請求的安全機制，後端需設定允許來源。

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. 行程與執行緒的差別？

- **行程**是作業系統分配資源的單位，擁有獨立的記憶體空間；一個行程崩潰通常不影響其他行程。
- **執行緒**是 CPU 排程的單位，同一行程內的執行緒**共享記憶體**，建立與切換成本較低。
- 取捨：執行緒溝通方便、效率高，但共享資料需要加鎖，否則會出現 Race Condition；行程隔離性好但溝通成本高（需透過 IPC）。

### Q2. 什麼是死結？如何避免？

兩個以上的執行緒互相等待對方持有的資源，導致全部永遠卡住。

發生需同時滿足四個條件：互斥、持有並等待、不可搶佔、循環等待。破壞任一條件即可避免，實務常用：
- **固定取鎖順序**（破壞循環等待）——最常用
- **設定取鎖逾時**，拿不到就放棄並重試
- **縮小鎖的範圍**，避免持有鎖時呼叫外部服務

### Q3. 從輸入網址到頁面出現發生了什麼？

1. **DNS 解析**：瀏覽器快取 → 作業系統 → DNS 伺服器，取得 IP
2. **建立 TCP 連線**：三次握手
3. **TLS 握手**（HTTPS）：驗證憑證、協商加密金鑰
4. **送出 HTTP 請求**，可能經過 CDN、負載平衡、反向代理到達應用伺服器
5. 伺服器處理並**回應 HTML**
6. 瀏覽器**解析 HTML、下載 CSS/JS、建立 DOM 與 CSSOM、排版並繪製**畫面

面試時可依職位深入某一段，例如後端可多談負載平衡與伺服器處理。

### Q4. TCP 三次握手為什麼是三次？

目的是讓**雙方都確認自己與對方「能送也能收」**，並同步初始序號。
1. 客戶端送 SYN：伺服器知道「客戶端能送」
2. 伺服器回 SYN+ACK：客戶端知道「伺服器能收也能送」
3. 客戶端回 ACK：伺服器知道「客戶端能收」

兩次不夠：伺服器無法確認客戶端收得到，且網路中延遲的舊 SYN 可能讓伺服器建立無效連線、浪費資源。

### Q5. 401 和 403 差在哪？

- **401 Unauthorized**：**沒有通過認證**——沒帶 Token、Token 過期或無效。客戶端應重新登入。
- **403 Forbidden**：**已知道你是誰，但沒有權限**——例如一般使用者存取管理功能。重新登入也沒用。

口訣：401 是「你是誰？」，403 是「我知道你是誰，但不准」。

### Q6. 為什麼金額不能用 float？

float / double 以二進位表示小數，很多十進位小數（如 0.1）**無法精確表示**，累加後會產生誤差，例如 `0.1 + 0.2 = 0.30000000000000004`。金額計算差一分錢都會造成對帳問題。

正確做法：
- 使用十進位型別：C# `decimal`、Java `BigDecimal`、資料庫 `DECIMAL(18,2)`
- 或以**最小單位的整數**儲存（例如以「分」為單位存 long）

## 本章回顧

- 執行緒共享記憶體 → 需要鎖 → 小心死結
- I/O 等待靠事件驅動解決，CPU 運算靠多核心解決
- 網路請求流程：DNS → TCP → TLS → HTTP
