# 17. 嵌入式與韌體（轉職橋接）

> **一句話**：韌體是「直接控制硬體的軟體」。最大差異在於**資源極少、時間要準、出錯可能燒壞硬體或無法遠端修復**。

---

## 1. 軟體 vs 韌體思維差異 🟢

| 面向 | 一般軟體 | 韌體 |
|---|---|---|
| 資源 | GB 等級記憶體 | KB～MB 等級 |
| 作業系統 | Windows / Linux | 無（裸機）、RTOS、或嵌入式 Linux |
| 時間要求 | 慢一點沒關係 | 常要求**在固定時間內必定完成**（即時性） |
| 出錯代價 | 重新部署 | 裝置變磚、硬體損壞、安全事故 |
| 除錯方式 | 中斷點、Log | 除錯器、示波器、邏輯分析儀 |
| 更新 | 隨時部署 | OTA 或實體燒錄，需非常謹慎 |

## 2. 硬體基本認識 🟢

### 2.1 MCU vs MPU

| | MCU（微控制器） | MPU（微處理器） |
|---|---|---|
| 特性 | 單一晶片內含 CPU、Flash、RAM、周邊 | 需外接記憶體 |
| 系統 | 裸機或 RTOS | 通常跑 Linux |
| 例子 | STM32、ESP32、nRF52 | 樹莓派、NXP i.MX |
| 用途 | 感測器、家電、穿戴裝置 | 閘道器、工控面板、車機 |

### 2.2 處理器架構

- **ARM Cortex-M**：MCU 主流
- **ARM Cortex-A**：手機、嵌入式 Linux
- **RISC-V**：開源指令集，快速成長中，值得關注

### 2.3 記憶體

- **Flash**：存放程式，斷電不消失
- **RAM（SRAM）**：存放執行中的變數，斷電消失，通常非常小
- 程式的記憶體配置由 **Linker Script** 決定

## 3. 核心觀念 🟡

| 觀念 | 白話 | 對應你的軟體經驗 |
|---|---|---|
| **GPIO** | 控制腳位輸出高低電位或讀取狀態（點亮 LED、讀按鈕） | — |
| **中斷（Interrupt）** | 硬體事件發生時立刻打斷主程式去處理 | 類似事件處理，但中斷處理程式必須**極短** |
| **暫存器操作** | 透過寫入特定記憶體位址控制硬體 | — |
| **輪詢 vs 中斷** | 一直檢查狀態 vs 等硬體通知 | 類似輪詢 API vs Webhook |
| **DMA** | 硬體直接搬移資料，不佔用 CPU | 類似非同步 I/O |
| **看門狗（Watchdog）** | 程式卡死時自動重啟系統 | 類似 K8s Liveness Probe |
| **`volatile`** | 告訴編譯器這個變數可能被硬體或中斷改變，不要最佳化掉 | — |
| **Bootloader** | 開機時第一個執行的程式，負責載入主程式或更新韌體 | — |

## 4. 通訊介面（面試必考）🟡

| 介面 | 特性 | 常見用途 |
|---|---|---|
| **UART** | 兩條線、非同步、簡單 | 除錯輸出、GPS、藍牙模組 |
| **I²C** | 兩條線、可掛多個裝置（用位址區分）、速度較慢 | 感測器、EEPROM |
| **SPI** | 四條線、全雙工、速度快 | 螢幕、Flash 記憶體、SD 卡 |
| **CAN** | 抗干擾、多節點、有優先權 | **汽車**、工業設備 |
| **USB、乙太網路** | 高速通訊 | 電腦連接、網路 |

**無線**：BLE（低功耗藍牙）、Wi-Fi、LoRa（長距離低功耗）、Matter（智慧家庭統一標準）。

**IoT 應用層協定**：**MQTT** —— 輕量的發佈 / 訂閱協定，概念與第 08 章的訊息佇列相同，是你軟體背景最好的切入點。

## 5. 語言與工具 🟡

- **C**：絕對主流，必須深入：指標、記憶體配置、位元運算、結構對齊
- **C++**：中大型韌體使用，通常限制使用例外與動態記憶體配置
- **Rust**：Embedded Rust 成長中，記憶體安全受安全關鍵產業關注
- **MISRA C**：車用等安全關鍵產業的 C 語言撰寫規範
- 工具：GCC ARM 編譯器、CMake、STM32CubeIDE、VS Code
- 除錯：JTAG / SWD 除錯器（J-Link、ST-Link）、GDB

## 6. RTOS 即時作業系統 🟡

**為什麼需要**：功能變多時，用一個大迴圈處理所有事情會很難維護，RTOS 讓你把功能拆成多個任務（Task）。

| 觀念 | 說明 |
|---|---|
| Task | 類似執行緒，每個有自己的優先權與 Stack |
| 優先權排程 | 高優先權任務一就緒就搶佔低優先權任務 |
| Queue / Semaphore / Mutex | 任務間溝通與同步（和第 01 章觀念相同） |
| **優先權反轉** | 低優先權任務持有鎖，導致高優先權任務被卡住 → 用優先權繼承解決（面試常問） |

**主流 RTOS**：**FreeRTOS**（最普及）、**Zephyr**（Linux 基金會主導，業界快速採用）。

**嵌入式 Linux**：功能更複雜的裝置使用，需了解 U-Boot、Device Tree、驅動程式、Yocto / Buildroot 建置系統。

## 7. 產業前沿需求 🔴

| 主題 | 重點 |
|---|---|
| **OTA 遠端更新** | A/B 雙分割區（新版失敗可退回舊版）、韌體簽章驗證 |
| **安全開機（Secure Boot）** | 開機時逐層驗證韌體簽章，防止被植入惡意韌體 |
| **資安法規** | 歐盟網路韌性法案（CRA）、車用資安 ISO 21434、工控 IEC 62443 → 產品需要漏洞管理與 SBOM |
| **功能安全** | 車用 ISO 26262：確保系統故障時不造成人身危險 |
| **低功耗設計** | 電池裝置需要睡眠模式與功耗量測 |
| **韌體測試與 CI** | 單元測試、模擬器（QEMU、Renode）、**HIL 硬體迴圈測試**、靜態分析 |
| **邊緣 AI** | 在 MCU 上執行小型 AI 模型（TinyML） |

## 8. 軟體工程師轉韌體 🟢

**你已具備的優勢**：
- Git、CI/CD、自動化測試 → 許多韌體團隊仍在補強這塊
- 架構設計、模組化思維
- 雲端後台、MQ → IoT 裝置與雲端串接
- Linux 操作

**需要補強**：
1. C 語言深度（指標、記憶體、位元運算）
2. 基本電子學：電壓、電流、上拉 / 下拉電阻
3. 看懂 **Datasheet**（晶片規格書）與電路圖
4. 硬體除錯工具
5. 即時系統與中斷思維

**建議學習路徑**：
```
ESP32 或 STM32 開發板
  → 裸機控制 GPIO、UART
  → I²C / SPI 讀取感測器
  → 導入 FreeRTOS 拆分任務
  → 透過 MQTT 上傳資料到雲端
  → 實作 OTA 更新
  → 整理成作品集（放 GitHub）
```

## 過時技術（知道就好）

- **8051 單晶片**：仍出現在教學與極低成本產品，新設計多採 ARM Cortex-M 或 RISC-V。
- **只用一個大迴圈（Super Loop）處理所有功能**：簡單裝置仍適用，功能複雜後會改用 RTOS。

## 本章回顧

- 韌體 = 資源少、時間準、出錯代價高
- 必懂：中斷、GPIO、UART / I²C / SPI、RTOS
- 你的軟體工程能力（CI、測試、架構）在韌體領域是加分項
