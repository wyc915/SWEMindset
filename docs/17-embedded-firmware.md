# 17. 嵌入式與韌體（轉職橋接）

> **一句話**：韌體是「直接控制硬體的軟體」。最大差異在於**資源極少、時間要準、出錯可能燒壞硬體或無法遠端修復**。

---

## 1. 軟體 vs 韌體思維差異 🟢

| 面向 | 一般軟體 | 韌體 |
|---|---|---|
| 資源 | GB 等級記憶體 | KB～MB 等級 |
| 作業系統 | Windows / Linux | 無（裸機）、RTOS、或嵌入式 Linux |
| 時間要求 | 慢一點沒關係 | 常要求**在固定時間內必定完成**（即時性） |
| 出錯代價 | 重新部署 | 裝置變磚、硬體損壞、安全事故 |
| 除錯方式 | 中斷點、Log | 除錯器、示波器、邏輯分析儀 |
| 更新 | 隨時部署 | OTA 或實體燒錄，需非常謹慎 |

## 2. 硬體基本認識 🟢

### 2.1 MCU vs MPU

| | MCU（微控制器） | MPU（微處理器） |
|---|---|---|
| 特性 | 單一晶片內含 CPU、Flash、RAM、周邊 | 需外接記憶體 |
| 系統 | 裸機或 RTOS | 通常跑 Linux |
| 例子 | STM32、ESP32、nRF52 | 樹莓派、NXP i.MX |
| 用途 | 感測器、家電、穿戴裝置 | 閘道器、工控面板、車機 |

### 2.2 處理器架構

- **ARM Cortex-M**：MCU 主流
- **ARM Cortex-A**：手機、嵌入式 Linux
- **RISC-V**：開源指令集，快速成長中，值得關注

### 2.3 記憶體

- **Flash**：存放程式，斷電不消失
- **RAM（SRAM）**：存放執行中的變數，斷電消失，通常非常小
- 程式的記憶體配置由 **Linker Script** 決定

## 3. 核心觀念 🟡

| 觀念 | 白話 | 對應你的軟體經驗 |
|---|---|---|
| **GPIO** | 控制腳位輸出高低電位或讀取狀態（點亮 LED、讀按鈕） | — |
| **中斷（Interrupt）** | 硬體事件發生時立刻打斷主程式去處理 | 類似事件處理，但中斷處理程式必須**極短** |
| **暫存器操作** | 透過寫入特定記憶體位址控制硬體 | — |
| **輪詢 vs 中斷** | 一直檢查狀態 vs 等硬體通知 | 類似輪詢 API vs Webhook |
| **DMA** | 硬體直接搬移資料，不佔用 CPU | 類似非同步 I/O |
| **看門狗（Watchdog）** | 程式卡死時自動重啟系統 | 類似 K8s Liveness Probe |
| **`volatile`** | 告訴編譯器這個變數可能被硬體或中斷改變，不要最佳化掉 | — |
| **Bootloader** | 開機時第一個執行的程式，負責載入主程式或更新韌體 | — |

## 4. 通訊介面（面試必考）🟡

| 介面 | 特性 | 常見用途 |
|---|---|---|
| **UART** | 兩條線、非同步、簡單 | 除錯輸出、GPS、藍牙模組 |
| **I²C** | 兩條線、可掛多個裝置（用位址區分）、速度較慢 | 感測器、EEPROM |
| **SPI** | 四條線、全雙工、速度快 | 螢幕、Flash 記憶體、SD 卡 |
| **CAN** | 抗干擾、多節點、有優先權 | **汽車**、工業設備 |
| **USB、乙太網路** | 高速通訊 | 電腦連接、網路 |

**無線**：BLE（低功耗藍牙）、Wi-Fi、LoRa（長距離低功耗）、Matter（智慧家庭統一標準）。

**IoT 應用層協定**：**MQTT** —— 輕量的發佈 / 訂閱協定，概念與第 08 章的訊息佇列相同，是你軟體背景最好的切入點。

## 5. 語言與工具 🟡

- **C**：絕對主流，必須深入：指標、記憶體配置、位元運算、結構對齊
- **C++**：中大型韌體使用，通常限制使用例外與動態記憶體配置
- **Rust**：Embedded Rust 成長中，記憶體安全受安全關鍵產業關注
- **MISRA C**：車用等安全關鍵產業的 C 語言撰寫規範
- 工具：GCC ARM 編譯器、CMake、STM32CubeIDE、VS Code
- 除錯：JTAG / SWD 除錯器（J-Link、ST-Link）、GDB

## 6. RTOS 即時作業系統 🟡

**為什麼需要**：功能變多時，用一個大迴圈處理所有事情會很難維護，RTOS 讓你把功能拆成多個任務（Task）。

| 觀念 | 說明 |
|---|---|
| Task | 類似執行緒，每個有自己的優先權與 Stack |
| 優先權排程 | 高優先權任務一就緒就搶佔低優先權任務 |
| Queue / Semaphore / Mutex | 任務間溝通與同步（和第 01 章觀念相同） |
| **優先權反轉** | 低優先權任務持有鎖，導致高優先權任務被卡住 → 用優先權繼承解決（面試常問） |

**主流 RTOS**：**FreeRTOS**（最普及）、**Zephyr**（Linux 基金會主導，業界快速採用）。

**嵌入式 Linux**：功能更複雜的裝置使用，需了解 U-Boot、Device Tree、驅動程式、Yocto / Buildroot 建置系統。

## 7. 產業前沿需求 🔴

| 主題 | 重點 |
|---|---|
| **OTA 遠端更新** | A/B 雙分割區（新版失敗可退回舊版）、韌體簽章驗證 |
| **安全開機（Secure Boot）** | 開機時逐層驗證韌體簽章，防止被植入惡意韌體 |
| **資安法規** | 歐盟網路韌性法案（CRA）、車用資安 ISO 21434、工控 IEC 62443 → 產品需要漏洞管理與 SBOM |
| **功能安全** | 車用 ISO 26262：確保系統故障時不造成人身危險 |
| **低功耗設計** | 電池裝置需要睡眠模式與功耗量測 |
| **韌體測試與 CI** | 單元測試、模擬器（QEMU、Renode）、**HIL 硬體迴圈測試**、靜態分析 |
| **邊緣 AI** | 在 MCU 上執行小型 AI 模型（TinyML） |

## 8. 軟體工程師轉韌體 🟢

**你已具備的優勢**：
- Git、CI/CD、自動化測試 → 許多韌體團隊仍在補強這塊
- 架構設計、模組化思維
- 雲端後台、MQ → IoT 裝置與雲端串接
- Linux 操作

**需要補強**：
1. C 語言深度（指標、記憶體、位元運算）
2. 基本電子學：電壓、電流、上拉 / 下拉電阻
3. 看懂 **Datasheet**（晶片規格書）與電路圖
4. 硬體除錯工具
5. 即時系統與中斷思維

**建議學習路徑**：
```
ESP32 或 STM32 開發板
  → 裸機控制 GPIO、UART
  → I²C / SPI 讀取感測器
  → 導入 FreeRTOS 拆分任務
  → 透過 MQTT 上傳資料到雲端
  → 實作 OTA 更新
  → 整理成作品集（放 GitHub）
```

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. UART、I²C、SPI 的差別？

| | UART | I²C | SPI |
|---|---|---|---|
| 線數 | 2（TX、RX） | 2（SDA 資料、SCL 時脈） | 4（MOSI、MISO、SCK、CS） |
| 同步 | 非同步（雙方約定鮑率） | 同步 | 同步 |
| 多裝置 | 點對點 | 一條匯流排掛多個裝置，用**位址**區分 | 每個裝置需要一條**CS 選擇線** |
| 速度 | 慢 | 中（常見 100k / 400kHz） | 快（數 MHz 至數十 MHz） |
| 雙工 | 全雙工 | 半雙工 | 全雙工 |
| 用途 | 除錯輸出、GPS、模組通訊 | 感測器、EEPROM | 顯示器、Flash、SD 卡 |

選擇原則：腳位少、裝置多、速度不高 → I²C；要求高速 → SPI；簡單點對點 → UART。

### Q2. `volatile` 的用途？

告訴編譯器：**這個變數可能在程式碼看不到的地方被改變**，每次存取都必須真的從記憶體讀寫，**不可以最佳化**（例如快取在暫存器、或刪除看似重複的讀取）。

常見使用時機：
- **硬體暫存器**（Memory-mapped I/O），值由硬體改變
- **中斷處理程式與主程式共用的變數**
- 多執行緒 / RTOS 任務共用的旗標

注意：`volatile` **不保證原子性，也不是鎖**。多位元組資料或「讀取-修改-寫入」操作仍需關閉中斷或使用 mutex 保護。

### Q3. 中斷處理程式為什麼要短？可以在裡面做什麼、不能做什麼？

**為什麼要短**：中斷執行時會打斷主程式，並可能**阻擋同級或更低優先權的中斷**。處理太久會造成其他中斷延遲或遺失、系統即時性變差。

**可以做**：
- 讀取硬體資料、清除中斷旗標
- 把資料放入緩衝區或佇列
- 設定旗標或通知 RTOS 任務（使用 ISR 專用 API，例如 FreeRTOS 的 `xQueueSendFromISR`）

**不應該做**：
- 長時間運算、延遲等待（`delay`）、迴圈輪詢
- `printf` 等慢速 I/O
- 動態記憶體配置（`malloc`）
- 呼叫會阻塞的函式或取得 mutex

原則：**ISR 只做最少的事，其他交給主迴圈或任務處理**（上半部 / 下半部設計）。

### Q4. 什麼是優先權反轉？怎麼解決？

**情境**：低優先權任務 L 持有一個 mutex，高優先權任務 H 需要這個 mutex 而等待。此時中優先權任務 M 就緒並搶佔 L，導致 L 無法執行、無法釋放 mutex → **H 被 M 間接卡住**，優先權順序被反轉。（著名案例：1997 年火星探路者號反覆重開機。）

**解法**：
- **優先權繼承**：L 持有 H 需要的鎖時，暫時把 L 提升到 H 的優先權，盡快執行完並釋放（FreeRTOS 的 mutex 支援）
- **優先權天花板**：鎖本身設定一個最高優先權，任何取得它的任務都暫時提升到該等級
- 設計上**縮短持鎖時間**，避免高低優先權任務共用資源

### Q5. MCU 與 MPU 的差別？

- **MCU（微控制器）**：單一晶片整合 CPU、Flash、RAM 與周邊（GPIO、UART、ADC…）。資源小（KB～MB）、功耗低、成本低、啟動快、即時性好，通常跑**裸機或 RTOS**。例：STM32、ESP32、nRF52。適合感測器、家電、穿戴裝置。
- **MPU（微處理器）**：只有運算核心，需外接 DRAM 與儲存裝置，效能強、通常有 MMU，可跑 **Linux** 等完整作業系統。例：NXP i.MX、樹莓派的處理器。適合閘道器、HMI 面板、車機。

選擇依據：是否需要複雜功能（網路堆疊、圖形介面、檔案系統）、即時性需求、功耗與成本。

### Q6. OTA 更新失敗時如何避免裝置變磚？

- **A/B 雙分割區**：新韌體寫入未使用的分割區，舊版本保持完整；寫入並驗證成功後才切換開機目標
- **完整性與簽章驗證**：下載後檢查雜湊與數位簽章，損壞或被竄改就拒絕安裝
- **開機確認與自動回滾**：新版開機後須在時限內「確認自己正常」，否則由 Bootloader 或看門狗自動回到舊版（例如 MCUboot 的 test / confirm 機制）
- **斷電保護**：任何時間點斷電都不會破壞目前可用的版本
- **保留安全的 Bootloader**：Bootloader 本身不透過一般 OTA 更新，確保永遠能進入恢復模式
- **分批推送**：先更新少量裝置觀察，類似金絲雀部署

### Q7. 看門狗的用途？

**看門狗（Watchdog Timer）**是一個硬體計時器，程式必須**定期「餵狗」（重設計時器）**；若程式卡死、陷入無窮迴圈或當機而沒有按時餵狗，計時器到期就會**自動重置系統**，讓裝置從異常狀態恢復。

使用要點：
- 在**確認系統健康**的地方餵狗，例如主迴圈或監控任務確認所有任務都正常回報後才餵，而不是在中斷中無條件餵狗
- 重置後記錄原因，方便追查問題
- 現場無人維護的裝置（IoT、工控）尤其重要

概念類似 K8s 的 Liveness Probe：偵測到不健康就重啟。

## 過時技術（知道就好）

- **8051 單晶片**：仍出現在教學與極低成本產品，新設計多採 ARM Cortex-M 或 RISC-V。
- **只用一個大迴圈（Super Loop）處理所有功能**：簡單裝置仍適用，功能複雜後會改用 RTOS。

## 本章回顧

- 韌體 = 資源少、時間準、出錯代價高
- 必懂：中斷、GPIO、UART / I²C / SPI、RTOS
- 你的軟體工程能力（CI、測試、架構）在韌體領域是加分項
