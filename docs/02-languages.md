# 02. 程式語言版圖與選型

> **一句話**：沒有最好的語言，只有最適合場景的語言。重點是知道每個語言「擅長什麼、代價是什麼」。

## 學習目標

- 說出主流語言的擅長領域與代價
- 比較編譯方式、型別系統、記憶體管理、併發模型四個關鍵差異
- 依需求、團隊與生態系為新專案提出有理由的語言選擇

---

## 1. 主流語言定位 🟢

| 語言 | 最擅長 | 為什麼 | 代價 |
|---|---|---|---|
| **C** | 韌體、驅動、作業系統 | 最貼近硬體、資源最省 | 記憶體錯誤全靠自己避免 |
| **C++** | 遊戲引擎、高效能系統、嵌入式 | 效能頂尖又有高階抽象 | 複雜、易寫出難維護的程式 |
| **Rust** | 系統程式、基礎設施、嵌入式（成長中） | 編譯期就擋掉記憶體錯誤，效能近 C | 學習曲線陡 |
| **Go** | 雲端服務、微服務、DevOps 工具 | 簡單、併發好寫、編譯成單一檔案好部署 | 語言表達力較弱 |
| **C# / .NET** | 企業系統、Web API、Windows 桌面、Unity 遊戲 | 工具與框架完整，效能佳，已跨平台 | 舊版 .NET Framework 包袱 |
| **Java / Kotlin** | 企業後端、Android、大數據 | 生態最成熟、人才多 | 較耗記憶體；Android 首選 Kotlin |
| **TypeScript / JavaScript** | 前端、Node.js 後端、全端 | 瀏覽器唯一原生語言，生態最大 | JS 型別鬆散 → 用 TS 補強 |
| **Python** | AI/ML、資料分析、自動化腳本 | 寫得快、AI 函式庫壟斷 | 執行慢，不適合高效能核心 |
| **SQL** | 資料查詢 | 所有關聯式資料庫通用 | 各家語法略有差異 |

**快速對照**：
- 做 AI → Python
- 做韌體 → C（Rust 成長中）
- 做雲原生工具 → Go
- 做企業後端 → C# / Java
- 做網頁 → TypeScript

## 2. 影響選型的核心概念 🟡

### 2.1 編譯 vs 直譯

- **編譯成機器碼**（C、C++、Rust、Go）：執行快，需針對平台編譯。
- **編譯成中間碼 + JIT**（C#、Java）：執行時再轉成機器碼，兼顧跨平台與效能。現在也支援 AOT（預先編譯），啟動更快、適合容器。
- **直譯**（Python、JS 原始概念）：開發快，執行相對慢（現代 JS 引擎有 JIT，已很快）。

### 2.2 靜態型別 vs 動態型別

- **靜態**（C#、Java、TS、Go）：編譯時就抓錯，大型專案好維護、IDE 提示強。
- **動態**（Python、JS）：寫起來快，但錯誤延到執行時才爆。
- 趨勢：動態語言也在加型別（TypeScript、Python Type Hints）。

### 2.3 記憶體管理方式

| 方式 | 語言 | 特性 |
|---|---|---|
| 手動 | C | 最可控，最容易出錯 |
| RAII（離開範圍自動釋放） | C++ | 可控且較安全 |
| 所有權（Ownership） | Rust | 編譯器強制安全，無 GC |
| GC 自動回收 | C#、Java、Go、JS、Python | 開發輕鬆，偶有暫停 |

> 這也是韌體偏好 C/C++/Rust 的原因：**時間要可預測，不能被 GC 暫停打斷**。

### 2.4 併發模型

- **執行緒 + 鎖**：傳統做法（Java、C#）
- **async/await**：I/O 等待不佔執行緒（C#、JS、Python、Rust）
- **Goroutine + Channel**：Go 的招牌，「用溝通取代共享記憶體」

## 3. 選型原則 🔴

1. **團隊熟悉度**通常比語言本身優劣更重要
2. **生態系**：有沒有成熟的框架、函式庫、雲端支援
3. **非功能需求**：延遲、記憶體、啟動時間、硬體限制
4. **招募與長期維護**：冷門語言找不到人

## 動手練習

1. **同題異語**：用你熟悉的 C# 與一個新語言（Go 或 Python）各寫一個讀取 JSON 並呼叫 API 的小程式，比較開發速度、型別檢查與部署方式。
2. **比較部署大小**：把同一個 Hello World API 分別用 .NET（一般發布與 Native AOT）與 Go 建成 Docker 映像，比較映像大小與啟動時間。

## 面試常問

> 先試著自己回答，再對照參考解答。

### Q1. 靜態型別與動態型別的優缺點？

| | 靜態型別（C#、Java、TS、Go） | 動態型別（Python、JS） |
|---|---|---|
| 優點 | 編譯期抓錯、IDE 提示與重構強、大型專案好維護、效能較好 | 寫得快、彈性大、適合腳本與原型 |
| 缺點 | 程式碼較冗長、初期開發較慢 | 錯誤延到執行時才發現、大型專案難維護 |

結論：團隊大、生命週期長的系統偏好靜態型別；這也是 TypeScript 與 Python 型別提示普及的原因。

### Q2. 什麼是 GC？為什麼即時系統不喜歡 GC？

**GC（垃圾回收）**由執行環境自動找出不再被使用的物件並釋放記憶體，開發者不用手動 free，能避免記憶體洩漏與重複釋放等錯誤。

即時系統（韌體、工控、高頻交易）不喜歡 GC，因為：
- GC 執行時可能**暫停程式（Stop-the-World）**，暫停時間**不可預測**
- 即時系統要求「某件事必須在固定時間內完成」，不確定的暫停可能造成錯過時限

因此這類系統多用 C / C++ / Rust，自行或由編譯器管理記憶體。

### Q3. C# 的 async/await 在解決什麼問題？

解決 **I/O 等待時執行緒被白白佔住**的問題。

- 同步呼叫資料庫或 API 時，執行緒會卡著等回應，伺服器執行緒很快被用完，無法處理更多請求
- 使用 `await` 時，等待期間**執行緒會被釋放**去處理其他請求，I/O 完成後再接續執行
- 結果：同樣的伺服器資源能承載更多併發請求，且程式碼仍維持接近同步的寫法

注意：async 不會讓單一請求變快，而是提升**吞吐量**；CPU 密集運算用 async 沒有幫助。避免使用 `.Result` / `.Wait()`，可能造成死結或執行緒耗盡。

### Q4. 為什麼雲原生工具多用 Go？

- **編譯成單一靜態執行檔**：不需安裝執行環境，容器映像極小、部署簡單
- **啟動快、記憶體佔用低**：適合大量部署的服務與 CLI 工具
- **原生併發**：goroutine 輕量，適合處理大量網路連線
- **語言簡單**：團隊上手快、程式風格一致，利於大型開源專案協作
- **跨平台編譯容易**

代表作：Docker、Kubernetes、Prometheus、Terraform、etcd。

### Q5. 你會怎麼為新專案選語言？

依序考量：
1. **需求與領域**：AI → Python；韌體 → C/C++；網頁前端 → TypeScript；高併發後端 → Go / C# / Java
2. **團隊熟悉度**：熟悉的語言交付最快、品質最好
3. **生態系**：是否有成熟的框架、函式庫、雲端與工具支援
4. **非功能需求**：效能、記憶體、啟動時間、部署環境限制
5. **長期維護與招募**：人才是否好找

回答時舉實例最好：「我們的後台團隊熟 .NET，且需要與既有 MSSQL 整合，所以選 ASP.NET Core。」
