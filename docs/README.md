# 軟體工程師必備常識知識庫

> 給初學者到中階工程師的「觀念地圖」。不教語法、不談演算法，只講**每個技術在解決什麼問題、何時用、面試會問什麼**。

## 閱讀方式

- 難度：🟢 基礎（入門必懂）｜🟡 進階（能獨立負責）｜🔴 高階（架構決策）
- 每章結構：**一句話重點 → 核心觀念 → 面試常問（附參考解答）→ 過時技術（知道就好）→ 本章回顧**
- 建議依「學習路線」順序閱讀，不必一次讀完

## 學習路線

| 階段 | 目標 | 對應章節 |
|---|---|---|
| 一、基礎 | 寫出能動的應用 | 01、02、03、04、05、06 |
| 二、工程化 | 交付可維護、可部署的服務 | 07、12、13（Docker）、14、15 |
| 三、系統化 | 設計可擴展、高可用系統 | 08、10、11、13（K8s） |
| 四、架構 | 做技術選型與取捨 | 09、19、18 |
| 韌體方向 | 轉職嵌入式 | 01 → 17（可與階段二並行） |

> 以 .NET / Vue / Node.js / MSSQL / MariaDB 背景為例，建議優先補：PostgreSQL（06）→ RabbitMQ / Kafka（08）→ Docker / K8s（13）→ CI/CD（14）→ 高併發與分散式（10、11）。
