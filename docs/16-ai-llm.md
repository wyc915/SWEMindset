# 16. AI 輔助開發與 LLM 應用

> **一句話**：AI 已經是工程師的日常工具，也是產品的常見功能。要會「用 AI 開發」，也要懂「把 AI 做進產品」的基本架構。

---

## 1. 用 AI 輔助開發 🟢

**常見工具**：Claude Code、GitHub Copilot、Cursor 等 AI 程式助理與 Agent。

**有效用法**：
- 給足上下文：需求、限制、現有架構、範例
- 要求**先說明規劃，再產生程式**
- 讓 AI 寫測試、解釋舊程式、產生文件、找 bug
- **一律自己審查與測試**：AI 會自信地寫出錯誤程式或不存在的 API

**風險**：
- 把公司機密或客戶資料貼到未經核准的服務
- 產生帶有安全漏洞的程式
- 過度依賴，自己不理解程式碼 → 面試與除錯時露餡

## 2. 大型語言模型（LLM）基本觀念 🟢

| 觀念 | 白話 |
|---|---|
| **Token** | 模型處理文字的單位，計費與長度限制都以 Token 計算 |
| **Context Window** | 模型一次能「看到」的內容長度上限 |
| **幻覺（Hallucination）** | 模型自信地編造錯誤資訊 |
| **Prompt** | 給模型的指示，清楚的角色、任務、範例、輸出格式能大幅提升品質 |

## 3. 把 AI 做進產品：常見架構 🟡

### 3.1 RAG（檢索增強生成）—— 最常見

**問題**：模型不知道你公司的內部文件，且可能過時或幻覺。

**做法**：
```
1. 事前：把文件切成小段 → 轉成向量（Embedding）→ 存入向量資料庫
2. 使用者提問 → 找出最相關的幾段文件
3. 把「問題 + 相關文件」一起交給模型回答
```

→ 讓回答有根據、可附上來源。**這也是本知識庫未來平台化最可能用到的架構。**

### 3.2 Tool Use（工具呼叫）

讓模型決定要呼叫哪個 API（查天氣、查訂單），由你的程式實際執行並把結果回傳給模型。

### 3.3 Agent（代理）

模型自主規劃步驟、反覆呼叫工具，直到完成任務。能力強，但需要權限控管與人工確認關鍵操作。

### 3.4 MCP（Model Context Protocol）

連接 AI 應用與外部工具 / 資料來源的開放標準。概念類似「AI 界的 USB 接口」：工具寫一次 MCP Server，各種 AI 應用都能接。

## 4. 上線 AI 功能要注意 🟡

| 面向 | 重點 |
|---|---|
| **評估（Evals）** | 準備測試題組，量化回答品質 —— AI 功能的「單元測試」 |
| **成本** | 依 Token 計費；用快取、選擇適當大小的模型控制成本 |
| **延遲** | 用串流（SSE）逐字輸出，改善使用者體感 |
| **安全** | **Prompt Injection**：使用者或文件內容中夾帶惡意指令，誘使模型做不該做的事 → 限制權限、驗證輸出 |
| **隱私** | 留意傳送給模型的資料是否含個資 |
